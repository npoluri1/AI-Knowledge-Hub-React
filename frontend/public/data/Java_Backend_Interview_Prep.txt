======================================================================================================================================================================================================================
INTERVIEW QUICK TIPS FOR SENIOR JAVA BACKEND
======================================================================================================================================================================================================================
1. Always go BEYOND the obvious — e.g., "ConcurrentHashMap" → mention computeIfAbsent atomically, resize during put, parallel streams caveat.
2. Microservices questions: discuss trade-offs explicitly (consistency vs availability, sync vs async).
3. System Design: start with requirements, estimate scale, then deep-dive on components. Use back-of-envelope calculation.
4. Production experience: frame answers with real incidents, root cause, resolution, and lessons learned (STAR method).
5. "Tell me about a conflict" → always frame around technical decisions (e.g., REST vs gRPC, monolith vs microservices).
6. For Java 21+ questions: mention Virtual Threads, StructuredTaskScope, Scoped Values, Record Patterns.
7. Ask clarifying questions before answering — shows senior thinking.
8. Own your gaps: "I haven't used that in production, but here's what I know..."
9. Prepare 2-3 "deep stories" about performance optimizations, outages, or migrations.

======================================================================================================================================================================================================================
#    | Concept        | Type             | Problem It Solves                     | How It Works / Key Insight
-----|----------------|------------------|---------------------------------------|----------------------------------------------------------------
168  | MCP (Model Context Protocol) | Tool Integration | Every new tool requires custom API code | Standardized protocol: MCP Client selects server → LLM routes to MCP Server (Slack, Qdrant, Brave) → data returned. No custom code per tool.
169  | RAG (Retrieval-Augmented Gen) | Knowledge Access | LLMs hallucinate on untrained data    | Data chunked → embeddings → Vector DB → user query triggers search → retrieved chunks + prompt → LLM output. Retrieves first, then reasons.
170  | Agent Skills   | Reusable Actions  | Repeating same instructions wastes tokens | Skill Manager retrieves stored prompts/actions (Git, Docker, Python, Shell) on demand. Loads only what's needed, exactly when needed.
171  | MCP — Discovery | Architecture      | Hardcoded tool integrations           | MCP servers announce capabilities at runtime. Model discovers tools; nothing is hardcoded. Moves intent, not just data.
