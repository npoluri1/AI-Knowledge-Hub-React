⬡ Overview & Engineering Philosophy

Key Insight

Teams spend weeks swapping embedding models chasing a 2% gain — while the pipeline bleeds 20% at a step most haven't even implemented.

The Uncomfortable Truth: In banking and healthcare, a hallucinated answer isn't embarrassing — it's a compliance incident. The failure modes in RAG pipelines are the same ones that have killed production systems for 16+ years: skipped validation, stale data, no audit trail.

Old Failure Modes, New Tech

  • → Chunking that splits ideas mid-thought
  • → Stale indexes serving last quarter's truth
  • → No reranker, so noise reaches context window
  • → No grounding check, so model fills gaps with confidence
  • → Notice what's NOT on the list: the embedding model

Pipeline-First Mindset

  • Fix pipeline fundamentals before tuning models
  • Hybrid search is non-negotiable for enterprise data
  • Reranking is the most skipped — and most impactful — step
  • Context is a built artifact with audit trail, never a dump
  • Every claim must be traceable to a source chunk

01 Step 1: User Query

Concept

The raw question from the user. It's vague, incomplete, and phrased nothing like your enterprise documents. A user asking "what changed last month?" might mean policy changes, pricing updates, or personnel shifts — the query carries no context about which index to search.

Python — User Query Handler
from dataclasses import dataclass from typing import Optional, Dict, Any import uuid import datetime # Schema for incoming query with full traceability @dataclass class UserQuery: query_id: str raw_text: str user_id: str session_id: str timestamp: datetime.datetime metadata: Dict[str, Any] domain: Optional[str] = None def capture_query(text: str, user: str, session: str, domain: Optional[str] = None) -> UserQuery: """Capture and log the raw query before any processing.""" return UserQuery( query_id=str(uuid.uuid4())[:8], raw_text=text, user_id=user, session_id=session, timestamp=datetime.datetime.now(), metadata={}, domain=domain ) # Real-world example: query = capture_query( text="tell me about the policy changes last quarter", user="usr_42", session="sess_7a3", domain="insurance" ) print(f"Logged query: {query.query_id}")

02 Step 2: Query Processing

Concept

The raw question is almost never the query you actually search with. Query processing includes rewriting, decomposition (splitting complex queries into sub-questions), and HyDE (Hypothetical Document Embeddings — generating a synthetic ideal document to search with instead of the query).

Python — Query Rewriting + Decomposition + HyDE
from typing import List import json # === Query Rewriting === def rewrite_query(raw: str, domain: str = "general") -> str: """Rewrite vague user query into precise search query.""" prompt = f"""Rewrite this user query into a clear, specific search query that would find relevant documents in a {domain} knowledge base. User: {raw} Search query:""" return llm.generate(prompt) # e.g., "billing dispute resolution policy Q3 2025" # === Query Decomposition === def decompose_query(query: str) -> List[str]: """Split complex query into parallel sub-queries.""" prompt = f"""Break this question into 2-4 simpler sub-questions that together answer the original question. Question: {query} Sub-questions (JSON list):""" result = llm.generate(prompt) return json.loads(result) # ["sub_q1", "sub_q2", ...] # === HyDE: Hypothetical Document Embeddings === def hyde_generate(query: str) -> str: """Generate a hypothetical ideal document that would answer the query. Search with THIS instead of the raw query.""" prompt = f"""Write a paragraph that would perfectly answer this question. Be specific and factual in style. Question: {query} Hypothetical document:""" return llm.generate(prompt) # Real-world usage: raw = "how do we handle refunds for cancelled flights" search_query = rewrite_query(raw, domain="airline_policy") hyde_doc = hyde_generate(search_query) # Now embed hyde_doc instead of raw query

Airline Customer Service — "my flight was cancelled" → Query rewritten to "cancelled flight refund policy 2025 + rebooking options + compensation policy." Sub-queries for refunds, rebooking, and EU-261 compensation run in parallel.

Use Case: Legal Document Search

Law Firm Discovery — "what cases relate to data breach liability in healthcare" → Decomposed into: (a) healthcare data breach statutes, (b) relevant case law 2020-2025, (c) liability precedents.

03 Step 3: Embedding

Concept

The query (or HyDE document) becomes a vector — a dense numerical representation that captures semantic meaning. Common models: OpenAI text-embedding-3-small (1536d), BGE-large-en-v1.5 (1024d), Cohere embed-english-v3.0. The embedding model is not the bottleneck — stop chasing 2% gains here.

Python — Embedding with Multiple Models
import numpy as np from typing import List, Union # Supported embedding models — normalize interface class EmbeddingEngine: def __init__(self, model: str = "text-embedding-3-small"): self.model = model if "openai" in model: from openai import OpenAI self.client = OpenAI() elif "bge" in model: from sentence_transformers import SentenceTransformer self.model_obj = SentenceTransformer(model) def encode(self, text: Union[str, List[str]]) -> np.ndarray: if "openai" in self.model: resp = self.client.embeddings.create( input=text if isinstance(text, list) else [text], model=self.model ) return np.array([d.embedding for d in resp.data]) else: return self.model_obj.encode(text) # Batch processing for production def batch_embed(texts: List[str], batch_size: int = 32) -> np.ndarray: engine = EmbeddingEngine() all_embeddings = [] for i in range(0, len(texts), batch_size): batch = texts[i:i+batch_size] all_embeddings.append(engine.encode(batch)) return np.vstack(all_embeddings)

Real-Time Application

E-Commerce Product Search — "red dress for summer wedding" → embedded and matched against 100K+ product descriptions. Multi-lingual embedding model handles mixed-language queries.

Use Case: Medical Research

Clinical Trial Matcher — Embed patient profiles and trial criteria; find matching trials by vector similarity across 50K+ trial records.

04 Step 4: Hybrid Search

Concept

Vector search catches meaning; BM25 catches exact terms. RRF (Reciprocal Rank Fusion) merges both ranked lists. In enterprise data — policy numbers, product codes, acronyms — pure vector search fails quietly every day. It's the first thing to check when someone says "our RAG doesn't work."

Python — Hybrid Search with RRF Fusion
from typing import List, Tuple, Dict import numpy as np # === RRF: Reciprocal Rank Fusion === def rrf_fusion( vec_results: List[Dict], bm25_results: List[Dict], k: int = 60 ) -> List[str]: """Fuse two ranked lists using reciprocal rank fusion. k=60 is the standard constant (RRF paper).""" scores: Dict[str, float] = {} for rank, doc in enumerate(vec_results): doc_id = doc["id"] scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank + 1) for rank, doc in enumerate(bm25_results): doc_id = doc["id"] scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank + 1) return sorted(scores, key=scores.get, reverse=True) # === Full Hybrid Search Pipeline === class HybridSearch: def __init__(self, vector_db, bm25_index): self.vector_db = vector_db self.bm25_index = bm25_index def search(self, query: str, query_vec: np.ndarray, k: int = 30) -> List[Dict]: # 1. Vector search — semantic vec_hits = self.vector_db.search(query_vec, k=k*2) # 2. BM25 search — exact term bm25_hits = self.bm25_index.search(query, k=k*2) # 3. RRF fusion fused_ids = rrf_fusion(vec_hits, bm25_hits) # 4. Return top-k with scores return fused_ids[:k] # Enterprise example: searching "CPT-99213 + follow-up visit protocol" # Vector catches "follow-up visit protocol" semantic # BM25 catches exact code "CPT-99213" # RRF ensures both contribute to final ranking

Real-Time Application

Healthcare Coding Search — Doctor searches "CPT-99213 follow-up hypertension" — BM25 catches the exact CPT code, vector search finds related hypertension management documents. RRF combines both for complete results.

Use Case: Legal Document Discovery

E-Discovery Platform — Search for "Section 230 immunity social media 2024" — vector finds conceptually related cases; BM25 catches exact statutory citations.

05 Step 5: Vector Database

Concept

Top-K comes back. K = 20–50, not 5. Recall first, precision later. The vector database stores embeddings + metadata and returns nearest neighbors. Production considerations: index type (HNSW, IVF), filterable metadata fields, namespacing for multi-tenant isolation.

Python — Vector Database Operations
from typing import List, Dict, Optional import numpy as np # === Abstract Vector DB Interface === class VectorDatabase: def search(self, vector: np.ndarray, k: int = 30, filter: Optional[Dict] = None) -> List[Dict]: # k=30 default: recall first, precision later raise NotImplementedError def upsert(self, docs: List[Dict]): raise NotImplementedError # === Qdrant Implementation === class QdrantDB(VectorDatabase): def __init__(self, collection: str, host: str = "localhost"): from qdrant_client import QdrantClient self.client = QdrantClient(host=host) self.collection = collection def search(self, vector: np.ndarray, k: int = 30, filter: Optional[Dict] = None) -> List[Dict]: from qdrant_client.http.models import Filter results = self.client.search( collection_name=self.collection, query_vector=vector.tolist(), limit=k, query_filter=Filter(**filter) if filter else None ) return [ {"id": r.id, "score": r.score, "payload": r.payload} for r in results ] def upsert(self, docs: List[Dict]): points = [ {"id": d["id"], "vector": d["vector"], "payload": d["payload"]} for d in docs ] self.client.upsert( collection_name=self.collection, points=points ) # Production: Namespace per tenant for isolation # K=50 initial recall → reranker filters to top 5

Multi-Tenant SaaS Knowledge Base — 500+ companies use the same RAG system. Each company gets a namespace (tenant_id filter). K=40 per namespace. Reranker narrows to 5 before generation.

Use Case: Compliance Document Search

Banking Regulation Platform — Search across 10K+ regulatory documents. Results filtered by jurisdiction (SG, US, EU), document type (guideline, statute, circular), and effective date range.

06 Step 6: Reranking ← The Step Everyone Skips

Most "broken" RAG systems are simply missing this step

A cross-encoder scores query + chunk together (not separately like bi-encoders). Twenty mediocre candidates become five great ones. In banking compliance, getting the exact policy clause to position 1 is not "nice to have" — it's a regulatory requirement.

Python — Cross-Encoder Reranking
from typing import List, Tuple import numpy as np class Reranker: def __init__(self, model_name: str = "BAAI/bge-reranker-v2-m3"): from transformers import AutoModelForSequenceClassification, AutoTokenizer self.tokenizer = AutoTokenizer.from_pretrained(model_name) self.model = AutoModelForSequenceClassification.from_pretrained(model_name) def rerank(self, query: str, documents: List[str], top_k: int = 5) -> List[Tuple[str, float]]: # Cross-encoder: score (query, doc) pair together import torch pairs = [(query, doc) for doc in documents] inputs = self.tokenizer( pairs, padding=True, truncation=True, return_tensors="pt", max_length=512 ) with torch.no_grad(): scores = self.model(**inputs).logits.squeeze(-1) scored = list(zip(documents, scores.tolist())) scored.sort(key=lambda x: x[1], reverse=True) return scored[:top_k] # === API-based reranker (simpler) === def rerank_cohere(query: str, docs: List[str], top_k: int = 5) -> List[int]: import cohere co = cohere.Client(api_key="...") results = co.rerank( query=query, documents=docs, model="rerank-english-v3.0", top_n=top_k ) return [(r.index, r.relevance_score) for r in results.results] # Production pipeline: 30 raw → reranker → 5 final candidates = vector_db.search(query_vec, k=30) docs_text = [c["text"] for c in candidates] top_5 = rerank_cohere(query, docs_text, top_k=5)

Real-Time Application

Banking Compliance Check — "What is our policy on account takeover refunds?" → 30 candidates retrieved → reranker ensures the exact compliance policy document is ranked #1. Missing this step would surface generic FAQ content instead.

Use Case: Medical Q&A

Clinical Decision Support — "Contraindications for Warfarin in elderly patients" → Reranker promotes the specific geriatric guideline to #1, demoting general Warfarin info that doesn't address elderly-specific risks.

07 Step 7: Context Assembly

Concept

Deduplicate, order by relevance, trim to token budget, and attach citations. In regulated environments, context is a built artifact with an audit trail — never a dump. Each chunk carries its source document ID, page number, version, and retrieval score.

Python — Context Assembly with Audit Trail
from dataclasses import dataclass, field from typing import List, Tuple import json @dataclass class ContextChunk: text: str source_doc: str page: int version: str score: float chunk_id: str @dataclass class BuiltContext: chunks: List[ContextChunk] = field(default_factory=list) total_tokens: int = 0 max_tokens: int = 4096 def add(self, chunk: ContextChunk) -> bool: tokens = len(chunk.text) // 4 # rough estimate if self.total_tokens + tokens > self.max_tokens: return False self.chunks.append(chunk) self.total_tokens += tokens return True def to_dict(self) -> dict: return { "total_tokens": self.total_tokens, "max_tokens": self.max_tokens, "chunks": [ {"source": c.source_doc, "page": c.page, "version": c.version, "score": c.score, "text_preview": c.text[:100]} for c in self.chunks ] } # === Build context with citations === def assemble_context(scored_docs: List[Tuple], max_tokens: int = 4096) -> BuiltContext: ctx = BuiltContext(max_tokens=max_tokens) for doc, score in scored_docs: chunk = ContextChunk( text=doc.text, source_doc=doc.metadata["source"], page=doc.metadata.get("page", 0), version=doc.metadata.get("version", "1.0"), score=score, chunk_id=f"{doc.id}" ) if not ctx.add(chunk): break return ctx # Serialize audit trail to JSON for compliance logging trace = ctx.to_dict() print(json.dumps(trace, indent=2)) # → ["source": "policy_v3.pdf", "page": 12, "version": "2.1", ...]

Real-Time Application

Regulatory Filing Assistant — Context assembled from 5 regulatory documents. Each chunk tagged with issuing body (MAS, SEC, FCA), effective date, and section number. Auditor can trace every answer to its source.

Use Case: Legal Contract Analysis

Contract Review System — Context built from 20 contract clauses. Each clause carries contract ID, clause number, and execution date. Token budget capped at 4096 — oldest/least relevant trimmed first.

08 Step 8: Generation

Concept

The model answers using only the assembled context. Instruct-tuned LLM with system prompt guardrails: "You are a helpful assistant. Answer based only on the provided context. If the context doesn't contain the answer, say 'I cannot find this information in the available documents.'"

Python — Generation with Guardrails
from typing import Optional class RAGGenerator: def __init__(self, model: str = "gpt-4"): from openai import OpenAI self.client = OpenAI() self.model = model SYSTEM_PROMPT = """You are a precise document analyst. Rules: 1. Answer ONLY from the provided context. 2. If the context doesn't have the answer, say so. 3. Cite the source document for each claim. 4. Do not use prior knowledge. 5. If unsure, say "I cannot verify this."""" def generate(self, context: "BuiltContext", query: str) -> str: context_text = "\n\n---\n\n".join( [f"[Source: {c.source_doc}, p.{c.page}] {c.text}" for c in context.chunks] ) messages = [ {"role": "system", "content": self.SYSTEM_PROMPT}, {"role": "user", "content": f"""Context: {context_text} Question: {query} Answer based only on the context above:"""} ] resp = self.client.chat.completions.create( model=self.model, messages=messages, temperature=0.1, max_tokens=1024 ) return resp.choices[0].message.content

Real-Time Application

Customer Support Agent — Context contains 3 policy documents about refunds. Model must synthesize answer from all 3. Temperature=0.1 ensures deterministic output. Source citations added to every paragraph.

Use Case: Financial Report Analysis

Q&A over Earnings Reports — "What was Q3 revenue growth by segment?" Context from 10-K filing. Model extracts exact figures per segment with page references.

09 Step 9: Grounding Check

No source? No claim. This is the difference between a demo and a system that survives an audit.

Every claim in the generated answer is traced back to a source chunk. If a claim can't be verified against the provided context, it's flagged or rejected. In healthcare and banking, this step is mandatory for compliance.

Python — Grounding Check with Claim Extraction
from typing import List, Tuple import re class GroundingChecker: def extract_claims(self, response: str) -> List[str]: """Split response into atomic claims (sentences/statements).""" sentences = re.split(r'(?<=[.?!])\s+', response) return [s.strip() for s in sentences if len(s) > 10] def check_claim(self, claim: str, context_chunks: List[str], threshold: float = 0.7) -> Tuple[bool, float]: """Check if a claim is supported by any context chunk. Uses embedding similarity + keyword overlap as fallback.""" best_score = 0.0 best_chunk = None for chunk in context_chunks: # Simple keyword overlap (in production, use NLI model) claim_words = set(claim.lower().split()) chunk_words = set(chunk.lower().split()) overlap = len(claim_words & chunk_words) / max(len(claim_words), 1) if overlap > best_score: best_score = overlap best_chunk = chunk return best_score >= threshold, best_score def validate(self, response: str, context_chunks: List[str]) -> List[Dict]: claims = self.extract_claims(response) results = [] for claim in claims: grounded, score = self.check_claim(claim, context_chunks) results.append({ "claim": claim, "grounded": grounded, "score": score }) return results # === Production: reject if any claim is ungrounded === def safe_generate(query: str, context: BuiltContext) -> str: gen = RAGGenerator() checker = GroundingChecker() response = gen.generate(context, query) context_texts = [c.text for c in context.chunks] results = checker.validate(response, context_texts) ungrounded = [r for r in results if not r["grounded"]] if ungrounded: return "I cannot verify this answer from the available sources." return response

Real-Time Application

Healthcare Answer Validation — "The recommended dosage of Warfarin for elderly patients is 2.5mg" → Checked against context chunks. If no chunk mentions "2.5mg" or "elderly" and "Warfarin" together, the claim is flagged as ungrounded.

Use Case: Financial Audit

Regulatory Filing Review — "Revenue grew 15% in Q3 2025" → Grounding checker verifies this exact number appears in the filed 10-Q document. If the context contains "revenue grew 12%", the mismatch is flagged.

⬡ Architecture Patterns

Pattern 1: Sequential Pipeline

Query → Process → Embed → Search → Rerank → Assemble → Generate → Ground → Answer

Simple, traceable, good for most enterprise RAG.

Pattern 2: Parallel Multi-Query

Query → Decompose → [SubQ1, SubQ2, SubQ3] → Parallel search → Merge → Rerank → Generate

Better for complex multi-faceted questions.

Pattern 3: Agentic Retrieval

Agent decides: when to search, what to search, which tool to use, whether results are sufficient

Emerging pattern — RAG becomes a tool the agent uses.

Pattern 4: Corrective RAG (CRAG)

Generate → Grounding Check → [Pass: answer] [Fail: rewrite search → re-retrieve → re-generate]

Self-correcting loop for high-accuracy needs.

⬡ Metrics & Observability

Retrieval Metrics

  • Recall@K: fraction of relevant docs in top-K
  • Precision@K: fraction of top-K that are relevant
  • MRR: Mean Reciprocal Rank of first relevant
  • NDCG@K: Normalized Discounted Cumulative Gain
  • Context Relevance: avg reranker score of assembled context

Generation Metrics

  • Grounding Pass Rate: % of claims verifiable in context
  • Faithfulness: NLI-based entailment score
  • Answer Relevance: cosine between query and answer
  • Latency P50/P95/P99: end-to-end pipeline timing
  • Cost Per Query: tokens in/out × model rates

from typing import List, Optional class RetrievalAgent: def __init__(self): self.tools = { "policy_search": HybridSearch(vector_db_policy, bm25_policy), "claims_search": HybridSearch(vector_db_claims, bm25_claims), "faq_search": HybridSearch(vector_db_faq, bm25_faq), } def decide_tool(self, query: str) -> str: """LLM decides which search tool to use.""" prompt = f"""Given this user question, which knowledge base should I search? - policy_search: for company policies, procedures - claims_search: for insurance claims processing - faq_search: for common questions Question: {query} Tool:""" return llm.generate(prompt).strip() def evaluate_results(self, query: str, results: List) -> bool: """Agent decides if results are sufficient to answer.""" prompt = f"""Given this question and the search results, can you fully answer the question? YES or NO. Question: {query} Results: {results[:500]} Answer:""" verdict = llm.generate(prompt).strip() return verdict == "YES" def retrieve(self, query: str, max_attempts: int = 3) -> List: """Agentic retrieval loop: decide → search → evaluate → repeat if needed""" for attempt in range(max_attempts): tool = self.decide_tool(query) searcher = self.tools[tool] results = searcher.search(query, k=30) if self.evaluate_results(query, results): return results # Refine query and try again query = rewrite_query(query + " [need more specific results]") return results # best effort after max_attempts

# === RAG Production Pipeline — Complete End-to-End === # FastAPI + Qdrant + Cross-Encoder + LLM + Grounding Check import os, time, json, uuid from typing import List, Optional, Tuple from dataclasses import dataclass, field, asdict import numpy as np from fastapi import FastAPI, HTTPException from pydantic import BaseModel app = FastAPI(title="RAG Production Pipeline") # ─── Data Models ─── class QueryRequest(BaseModel): text: str user_id: str = "anonymous" session_id: str = "default" class RAGResponse(BaseModel): answer: str grounded: bool latency_ms: float sources: List[str] # ─── Step 1: Capture Query ─── def capture_query(req: QueryRequest) -> dict: return {"query_id": str(uuid.uuid4())[:8], "raw_text": req.text, "user_id": req.user_id, "session_id": req.session_id, "timestamp": time.strftime("%Y-%m-%dT%H:%M:%S")} # ─── Step 2: Query Processing ─── def rewrite_query(text: str) -> str: """Use LLM to rewrite vague query into specific search query.""" prompt = f"Rewrite for search: {text}\nSearch query:" return llm_generate(prompt) # ─── Step 3: Embedding ─── def embed_query(text: str) -> np.ndarray: return embedding_engine.encode(text) # ─── Step 4: Hybrid Search (Vector + BM25 + RRF) ─── def hybrid_search(query: str, query_vec: np.ndarray, k: int = 30) -> List[dict]: vec_results = vector_db.search(query_vec, k=k*2) bm25_results = bm25_index.search(query, k=k*2) # RRF fusion scores = {} for rank, r in enumerate(vec_results): scores[r["id"]] = scores.get(r["id"], 0) + 1/(60+rank) for rank, r in enumerate(bm25_results): scores[r["id"]] = scores.get(r["id"], 0) + 1/(60+rank) ranked = sorted(scores, key=scores.get, reverse=True) return [doc_map[_id] for _id in ranked[:k]] # ─── Step 6: Reranking ─── def rerank(query: str, docs: List[dict], top_k: int = 5) -> List[dict]: pairs = [(query, d["text"]) for d in docs] scores = reranker.predict(pairs) scored = list(zip(docs, scores)) scored.sort(key=lambda x: x[1], reverse=True) return [d for d, _ in scored[:top_k]] # ─── Step 7: Context Assembly ─── def assemble_context(docs: List[dict], max_tokens: int = 4096) -> Tuple[str, List[str]]: chunks, sources, tokens = [], [], 0 for d in docs: estimated = len(d["text"]) // 4 if tokens + estimated > max_tokens: break chunks.append(d["text"]) sources.append(d.get("source", "unknown")) tokens += estimated return "\n\n---\n\n".join(chunks), sources # ─── Step 8: Generation ─── def generate_answer(query: str, context: str) -> str: system = "Answer ONLY from the context. Cite sources. Say 'not found' if unsure." return llm_generate(system + "\nContext:\n" + context + "\nQ: " + query) # ─── Step 9: Grounding Check ─── def check_grounding(answer: str, context: str) -> Tuple[bool, float]: claims = [s.strip() for s in answer.split(".") if len(s) > 10] grounded = 0 for claim in claims: if any(claim.lower() in chunk.lower() for chunk in context.split("\n\n---\n\n")): grounded += 1 rate = grounded / max(len(claims), 1) return rate >= 0.8, rate # ─── API Endpoint ─── @app.post("/rag/query", response_model=RAGResponse) def rag_query(req: QueryRequest): start = time.time() q = capture_query(req) rewritten = rewrite_query(q["raw_text"]) vec = embed_query(rewritten) candidates = hybrid_search(rewritten, vec) top_docs = rerank(rewritten, candidates) context, sources = assemble_context(top_docs) answer = generate_answer(rewritten, context) grounded, rate = check_grounding(answer, context) latency = round((time.time() - start) * 1000, 2) if not grounded: answer = "I cannot verify this answer from available sources." return RAGResponse(answer=answer, grounded=grounded, latency_ms=latency, sources=sources) # Run: uvicorn rag_pipeline:app --reload # Test: curl -X POST http://localhost:8000/rag/query \ # -H "Content-Type: application/json" \ # -d '{"text": "what are the refund policies for cancelled orders"}'
