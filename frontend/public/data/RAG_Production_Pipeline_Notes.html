01 Python Foundations

Async Programming (asyncio)

Single-threaded concurrency using coroutines (async/await), event loops, and tasks. Critical for AI APIs where you need to fetch from multiple LLMs/vector DBs concurrently. The event loop schedules coroutines cooperatively — they yield control at await points.

  • Key APIs: asyncio.run(), asyncio.create_task(), asyncio.gather(), asyncio.wait_for(), asyncio.as_completed()
  • Concurrency vs parallelism: asyncio is concurrent (one thread, many tasks), not parallel (multi-core). Use concurrent.futures for CPU-bound work.

02 LLM Fundamentals

Tokens, Tokenization & Embeddings

LLMs process text as tokens (subword units via BPE/WordPiece). Embeddings are dense vector representations that capture semantic meaning. Similarity is measured via cosine distance.

  • Tokenizers: tiktoken (OpenAI), tokenizers (HuggingFace)
  • Embedding models: text-embedding-3-small, voyage-2, BGE, E5
  • Context window: Modern LLMs support 8K–200K tokens. Window management is critical for RAG.
  • Temperature / Top-P: Controls randomness. Low temp (0–0.3) for factual; high (0.7–1.0) for creative.
Code: Token Counting + Embedding Generation
import tiktoken from openai import OpenAI import numpy as np client = OpenAI() def count_tokens(text: str, model: str = "cl100k_base") -> int: enc = tiktoken.get_encoding(model) return len(enc.encode(text)) def get_embedding(text: str) -> list[float]: resp = client.embeddings.create( model="text-embedding-3-small", input=text ) return resp.data[0].embedding def cosine_similarity(a: list[float], b: list[float]) -> float: a, b = np.array(a), np.array(b) return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)) text = "RAG systems retrieve documents before generation" print(f"Tokens: {count_tokens(text)}") embed = get_embedding(text) print(f"Embedding dim: {len(embed)}")

03 RAG Pipeline

Retrieval-Augmented Generation — Architecture

RAG injects external knowledge into LLM prompts at inference time. The core cycle: Index → Retrieve → Augment → Generate. No retraining needed — the knowledge base is updated independently.

  • Chunking: Recursive split (fixed size), semantic split (by meaning), agentic split (LLM decides boundaries)
  • Retrieval: Dense (embedding search), Sparse (BM25 keyword), Hybrid (weighted combined)
  • Augmentation: Context window packing with priority ordering
Code: Complete RAG Pipeline (Index → Retrieve → Generate)
from langchain.text_splitter import RecursiveCharacterTextSplitter from langchain_chroma import Chroma from langchain_openai import OpenAIEmbeddings, ChatOpenAI from langchain.chains import create_retrieval_chain from langchain.chains.combine_documents import create_stuff_documents_chain from langchain_core.prompts import ChatPromptTemplate def build_rag_pipeline(documents: list[str]): # 1. Chunk splitter = RecursiveCharacterTextSplitter( chunk_size=512, chunk_overlap=64) chunks = splitter.create_documents(documents) # 2. Embed & Index embeddings = OpenAIEmbeddings(model="text-embedding-3-small") vectorstore = Chroma.from_documents(chunks, embeddings) # 3. Retrieve retriever = vectorstore.as_retriever( search_type="mmr", search_kwargs={"k": 5, "fetch_k": 20}) # 4. Generate prompt = ChatPromptTemplate.from_messages([ ("system", "Answer using ONLY the provided context. " r"If unsure, say \"I don't know.\"\n\nContext: {context}"), ("human", "{input}")]) llm = ChatOpenAI(model="gpt-4o", temperature=0) chain = create_stuff_documents_chain(llm, prompt) return create_retrieval_chain(retriever, chain) # Usage chain = build_rag_pipeline(["RAG was introduced in 2020 by Lewis et al."]) result = chain.invoke({"input": "When was RAG introduced?"}) print(result["answer"])

05 Agent Frameworks (LangChain / LangGraph / CrewAI)

LangChain LCEL + Tool Calling

LangChain Expression Language (LCEL) provides a declarative way to chain LLM calls, tools, and retrievers. The @tool decorator converts any Python function into an LLM-callable tool with auto-generated schema.

Code: LangChain Agent with Tools

LangGraph — Stateful Graph-Based Agents

LangGraph models agent workflows as a state machine: nodes (functions), edges (transitions), and conditional edges (decisions). Built-in support for human-in-the-loop via interrupt/checkpoint.

Code: LangGraph Agent with Human-in-Loop
from typing import TypedDict, Literal from langgraph.graph import StateGraph, END from langgraph.checkpoint.memory import MemorySaver class AgentState(TypedDict): query: str retrieved_docs: list needs_approval: bool answer: str def retrieve_node(state: AgentState) -> dict: docs = search_db(state["query"]) return {"retrieved_docs": docs} def classify_node(state: AgentState) -> dict: if "confidential" in str(state["retrieved_docs"]): return {"needs_approval": True} return {"needs_approval": False} def router(state: AgentState) -> Literal["approval", "generate"]: return "approval" if state["needs_approval"] else "generate" builder = StateGraph(AgentState) builder.add_node("retrieve", retrieve_node) builder.add_node("classify", classify_node) builder.add_node("generate", lambda s: {"answer": llm.invoke(s["query"])}) builder.set_entry_point("retrieve") builder.add_edge("retrieve", "classify") builder.add_conditional_edges("classify", router) builder.add_edge("generate", END) graph = builder.compile(checkpointer=MemorySaver())

06 Agent Protocols (MCP / A2A / ACP)

MCP — Model Context Protocol (Anthropic)

Open standard for connecting LLMs to external tools and data sources. An MCP host (the LLM app) connects to MCP servers that expose tools, resources, and prompts. The client manages the connection.

  • Tools: Functions the LLM can call (read file, query DB, send email)
  • Resources: Data the LLM can read (file contents, API responses)
  • Prompts: Reusable prompt templates
Code: MCP Python Server (Tool + Resource + Prompt)
from mcp.server.fastmcp import FastMCP server = FastMCP("Knowledge Base MCP") @server.tool() def query_docs(query: str, max_results: int = 5) -> list[str]: """Search the knowledge base for relevant documents.""" return [f"Doc {i}: result for {query}" for i in range(max_results)] @server.resource("config://app") def get_config() -> str: """Application configuration.""" return '{"version": "2.0", "features": ["rag", "agents"]}' @server.prompt() def rag_query(question: str) -> str: """Format a question for RAG-style answering.""" return f"Answer the question based on available knowledge: {question}" server.run(transport="stdio")

08 Advanced RAG Variants

KAG / CAG / CRAG / Vectorless RAG

  • KAG (Knowledge-Augmented Gen): Uses structured knowledge graphs instead of flat vectors. Best for regulated domains with fixed ontologies.
  • CAG (Cache-Augmented Gen): Semantic caching for repeated queries. Sub-second on cache hit. Needs TTL/eviction strategy.
  • CRAG (CAG + RAG Hybrid): Cache first → miss → RAG. Best of both worlds.
  • Vectorless RAG: BM25/sparse/LLM-as-retriever. No embedding costs. Good for keyword-heavy data.
Code: Semantic Cache (CAG) Implementation
import hashlib, json, time from redis import Redis from openai import OpenAI client = OpenAI() redis_client = Redis(host="localhost", port=6379, decode_responses=True) class SemanticCache: def __init__(self, threshold: float = 0.92, ttl: int = 3600): self.threshold = threshold; self.ttl = ttl def _embed(self, text: str) -> list[float]: return client.embeddings.create( model="text-embedding-3-small", input=text).data[0].embedding def get(self, query: str) -> str | None: q_emb = self._embed(query) for key in redis_client.scan_iter("cache:*"): cached = json.loads(redis_client.get(key)) sim = cosine_similarity(q_emb, cached["embedding"]) if sim >= self.threshold: return cached["response"] return None def set(self, query: str, response: str): key = f"cache:{hashlib.md5(query.encode()).hexdigest()}" redis_client.setex(key, self.ttl, json.dumps({ "embedding": self._embed(query), "response": response}))
