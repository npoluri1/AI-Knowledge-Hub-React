1Install, REPL, and IDE Setup

What & why. Python installation has matured: the official installer bundles pip, IDLE, and the standard library. The REPL (Read-Eval-Print Loop) is your sandbox for rapid experimentation. Modern IDEs like VS Code with Pylance or PyCharm provide IntelliSense, debugging, and formatting out of the box.

# Verify installation
$ python --version
Python 3.13.1

# Launch the interactive REPL
$ python
>>> import sys
>>> sys.version_info

# Per-project virtual environment
$ python -m venv .venv
$ .venv\Scripts\activate

Where you'll use itEvery Python project starts here. Virtual environments keep dependency isolation clean, and the REPL is used for quick prototyping, debugging, and testing snippets before committing to files.
Under the hoodCPython compiles source to bytecode (.pyc) stored in __pycache__. The REPL uses the code module internally, and python -m venv copies the interpreter binary plus pip into an isolated directory tree with rewritten paths.

2Variables and Dynamic Typing

What & why. Python variables are names bound to objects — they carry no type information themselves. Assignment uses = and the name resolves to whatever object it currently references. This dynamic typing enables rapid prototyping but demands discipline through type hints and linting.

# Names are references, not typed slots
x = 42          # x → int object 42
x = "hello"     # x → str object (int 42 is unreferenced)
x = [1, 2, 3]   # x → list object

# Multiple assignment and swapping
a, b, c = 1, 2, 3
a, b = b, a     # swap without temp variable

# Identity vs equality
lst1 = [1, 2]
lst2 = [1, 2]
print(lst1 == lst2)   # True  — same value
print(lst1 is lst2)   # False — different objects

# Inspect what a name references
print(type(x))  # <class 'list'>
Where you'll use itEvery line of Python uses variable binding. Understanding reference semantics prevents bugs around mutable default arguments, shared references, and unexpected aliasing in functions.
Under the hoodCPython uses reference counting as the primary memory management strategy. Each object has an ob_refcnt incremented when a new name references it. When refcount hits zero, the object is deallocated immediately or added to the generational garbage collector for cycles.

3Int, Float, and Complex Numbers

What & why. Python integers have arbitrary precision — no overflow. Floats follow IEEE 754 double-precision, and complex numbers are first-class with j suffix. The decimal and fractions modules handle exact arithmetic when floating-point errors are unacceptable.

# Arbitrary-precision integers
big = 10 ** 100
print(big.bit_length())  # 333 bits

# Float precision pitfalls
print(0.1 + 0.2)         # 0.30000000000000004
print(0.1 + 0.2 == 0.3)  # False

# Use math.isclose for float comparison
import math
print(math.isclose(0.1 + 0.2, 0.3))  # True

# Complex numbers
z = 3 + 4j
print(z.real, z.imag)    # 3.0 4.0
print(abs(z))             # 5.0 (magnitude)
print(z.conjugate())     # (3-4j)

# Exact arithmetic
from fractions import Fraction
from decimal import Decimal
print(Fraction(1, 3) + Fraction(1, 6))  # 1/2
print(Decimal('0.1') + Decimal('0.2'))  # 0.3
Where you'll use itFloating-point comparison is the number one source of numerical bugs. Financial systems use Decimal, scientific computing uses numpy, and equality checks always use math.isclose with tolerances.
Under the hoodCPython stores each int as a variable-length array of 30-bit digits (PyLongObject), allowing arbitrary precision. Floats map directly to C doubles. Complex numbers are two doubles stored in a single PyComplexObject.

4Strings and Methods

What & why. Strings in Python 3 are Unicode by default (UTF-8 internally). They are immutable — every method returns a new string. Python provides a rich set of string methods for searching, transforming, and formatting.

s = "  Hello, World!  "

print(s.strip())            # "Hello, World!"
print(s.strip().lower())    # "hello, world!"
print(s.strip().upper())    # "HELLO, WORLD!"
print(s.strip().replace("World", "Python"))  # "Hello, Python!"

print("hello".startswith("he"))   # True
print("hello".endswith("lo"))     # True
print("abc123".isalnum())         # True
print("abc123".find("12"))        # 3

csv_line = "alice,bob,charlie"
names = csv_line.split(",")
print(" & ".join(names))  # "alice & bob & charlie"

data = "caf\u00e9".encode("utf-8")
print(data.decode("utf-8"))

print("=" * 40)     # 40 equals signs
print("x" in "xyz") # True
Where you'll use itString manipulation is the bread and butter of text processing — parsing log files, cleaning data, building HTTP responses, generating reports, and template rendering.
Under the hoodPython 3.12+ uses a flexible string representation: compact ASCII (1 byte/char), compact Latin-1 (1 byte/char), or flexible Unicode (1, 2, or 4 bytes/char) depending on the widest codepoint.

5f-strings and format()

What & why. f-strings (formatted string literals, Python 3.6+) are the preferred way to embed expressions in strings. They support debugging with = syntax (3.8+), and in 3.12+ allow nested quotes and multiline expressions.

name, score, pct = "Alice", 95, 0.9234

print(f"Hello, {name}!")  # "Hello, Alice!"
print(f"{name=}, {score=}")  # name='Alice', score=95

print(f"Score: {score:.2f}")      # "Score: 95.00"
print(f"Percent: {pct:.1%}")      # "Percent: 92.3%"
print(f"Name: {name:<10}")        # "Name: Alice     "
print(f"Hex: {255:#x}")           # "Hex: 0xff"

data = {"x": 10, "y": 20}
print(f"Coords: ({data['x']}, {data['y']})")

msg = (
    f"Name: {name}\n"
    f"Score: {score}\n"
    f"Pass: {'yes' if score >= 60 else 'no'}"
)
print(msg)
Where you'll use itf-strings are used everywhere: logging messages, SQL query construction, HTML templating, CLI output formatting. They are faster than both format() and % formatting.
Under the hoodf-strings compile to efficient bytecode that calls __format__ on each embedded object. Python 3.12 rewrote the f-string parser to handle nested expressions and arbitrary string content inside braces.

6Booleans and Truthiness

What & why. bool is a subclass of int — True equals 1 and False equals 0. Python defines truthiness for every object: empty containers, zero, None, and False are falsy; everything else is truthy.

# Booleans are ints
print(True + True)    # 2
print(True * 10)      # 10

falsy = [None, False, 0, 0.0, 0j, "", [], (), {}, set(), frozenset()]
for val in falsy:
    assert not val

items = [1, 2, 3]
if items:                    # empty list is falsy
    print("has items")

name = ""
display = name or "Anonymous"  # short-circuit to default

nums = [2, 4, 6, 8]
print(all(n % 2 == 0 for n in nums))  # True
print(any(n > 5 for n in nums))        # True

print(bool("hello"))  # True
print(bool(""))       # False
Where you'll use itTruthiness is the backbone of Pythonic conditional logic. It eliminates verbose null checks, enables default-value patterns with or, and powers any/all.
Under the hoodEvery Python object has a __bool__ method. If not defined, Python falls back to __len__, then always truthy. The or operator short-circuits: it returns the first truthy operand or the last operand.

7Lists

What & why. Lists are mutable, ordered, heterogeneous sequences. They support append, insert, remove, pop, sort, and list comprehension. Under the hood, they are dynamic arrays with amortized O(1) appends.

nums = [3, 1, 4, 1, 5, 9]
nums.append(2)         # [3, 1, 4, 1, 5, 9, 2]
nums.insert(0, 0)      # [0, 3, 1, 4, 1, 5, 9, 2]
nums.remove(1)         # removes first occurrence
popped = nums.pop()    # removes and returns last
nums.extend([6, 7])    # in-place concatenation

nums.sort()            # in-place sort
sorted_copy = sorted(nums)  # returns new list

squares = [x ** 2 for x in range(10)]
evens = [x for x in range(20) if x % 2 == 0]

matrix = [[i * j for j in range(1, 4)] for i in range(1, 4)]
# [[1, 2, 3], [2, 4, 6], [3, 6, 9]]

first, *middle, last = [1, 2, 3, 4, 5]
print(middle)  # [2, 3, 4]

copy1 = nums[:]
copy2 = list(nums)
Where you'll use itLists are used for ordered collections, stacks (append/pop), queues (with collections.deque), data pipelines via comprehensions, and as the backbone of most algorithms.
Under the hoodCPython lists are C arrays of PyObject pointers. When full, it over-allocates (~12.5%) for amortized O(1) appends. Removal from the front is O(n) because all elements shift.

8Tuples

What & why. Tuples are immutable, ordered sequences. They are faster than lists, can be dictionary keys and set members (if hashable), and are the language's mechanism for multiple return values.

point = (3, 4)
single = (42,)      # trailing comma required
empty = ()

x, y = point
print(f"Distance: {(x**2 + y**2) ** 0.5}")  # 5.0

locations = {(35.68, 139.69): "Tokyo", (48.85, 2.35): "Paris"}

from typing import NamedTuple
class User(NamedTuple):
    name: str
    age: int
    active: bool = True

u = User("Alice", 30)
print(u.name, u.active)  # Alice True

def min_max(items):
    return min(items), max(items)

lo, hi = min_max([3, 1, 4, 1, 5])
Where you'll use itTuples represent fixed-structure records: coordinates, RGB values, function return pairs, database rows, and dictionary keys.
Under the hoodTuples are stored as a single contiguous block of PyObject pointers but the tuple object itself is immutable. Their hashability comes from a stable __hash__ that hashes based on content.

9Sets

What & why. Sets are unordered collections of unique, hashable elements. They excel at membership testing (O(1) average), deduplication, and set algebra (union, intersection, difference).

a = {1, 2, 3, 4}
b = {3, 4, 5, 6}
empty = set()  # NOT {} which creates an empty dict

unique = set([1, 2, 2, 3, 3, 3])  # {1, 2, 3}

print(a | b)   # union:        {1, 2, 3, 4, 5, 6}
print(a & b)   # intersection: {3, 4}
print(a - b)   # difference:   {1, 2}
print(a ^ b)   # symmetric:    {1, 2, 5, 6}

print({1, 2} <= {1, 2, 3})   # True

ascii_vals = {ord(c) for c in "hello" if c.isalpha()}
fs = frozenset([1, 2, 3])
Where you'll use itSets are essential for deduplicating data, membership testing against white/blacklists, finding common or unique elements, and graph algorithms.
Under the hoodSets are hash tables with open addressing. Insertion and lookup are O(1) amortized. The table resizes at 2/3 capacity.

10Dictionaries

What & why. Dicts map unique keys to values. Since Python 3.7, insertion order is guaranteed. Dicts power namespaces, JSON, configuration, and countless libraries.

user = {"name": "Alice", "age": 30, "active": True}
fromkeys = dict.fromkeys(["a", "b", "c"], 0)

print(user["name"])                    # KeyError if missing
print(user.get("email", "N/A"))       # safe with default
print(user.setdefault("role", "user")) # insert if missing

user |= {"email": "alice@example.com"}  # 3.9+ in-place merge
merged = user | {"age": 31}             # new dict

for key, value in user.items():
    print(f"{key}: {value}")

squares = {x: x**2 for x in range(6)}

from collections import defaultdict
words = ["apple", "banana", "avocado", "blueberry"]
by_first = defaultdict(list)
for word in words:
    by_first[word[0]].append(word)
Where you'll use itDicts are ubiquitous — JSON is dicts, objects are dicts of attributes, caches are dicts. Almost every Python library uses dicts for configuration and data interchange.
Under the hoodPython 3.6+ dicts use a compact hash table with an auxiliary indices array. Insertion order is preserved by storing entries in insertion sequence. O(1) average lookup.

11range() and Looping Patterns

What & why. range() generates integer sequences lazily — constant memory regardless of size. Combined with enumerate, zip, and reversed, it forms the backbone of Python iteration.

print(list(range(5)))          # [0, 1, 2, 3, 4]
print(list(range(2, 10, 2)))   # [2, 4, 6, 8]
print(list(range(10, 0, -1)))  # [10, 9, 8, ..., 1]

fruits = ["apple", "banana", "cherry"]
for i, fruit in enumerate(fruits, start=1):
    print(f"{i}. {fruit}")

names = ["Alice", "Bob", "Charlie"]
scores = [95, 87, 91]
for name, score in zip(names, scores):
    print(f"{name}: {score}")

from itertools import zip_longest
a = [1, 2, 3]; b = ["x", "y"]
print(list(zip_longest(a, b, fillvalue="-")))

for val in reversed(range(5)):
    print(val, end=" ")  # 4 3 2 1 0

def find_item(lst, target):
    for item in lst:
        if item == target:
            break
    else:
        print(f"{target} not found")
Where you'll use itThese patterns appear in every Python script. enumerate eliminates index bugs, zip enables parallel processing, range generates indices for numeric algorithms.
Under the hoodrange is a dedicated type that generates values on demand. zip and enumerate are iterator types that pull lazily from their underlying iterables.

12if / elif / else

What & why. Python's conditional logic uses keywords instead of braces. The ternary expression and walrus operator (:=, 3.8+) provide inline conditional capabilities.

score = 85
if score >= 90:
    grade = "A"
elif score >= 80:
    grade = "B"
elif score >= 70:
    grade = "C"
else:
    grade = "F"

status = "pass" if score >= 60 else "fail"

import re
text = "Call 555-1234 or 555-5678"
while match := re.search(r"\d{3}-\d{4}", text):
    print(match.group())
    text = text[match.end():]

x = 5

    print("single digit positive")

data = []

    print("empty")
Where you'll use itConditionals drive all program logic: input validation, feature flags, configuration branching, error recovery paths, and state machine transitions.
Under the hoodPython compiles conditionals to POP_JUMP_IF_FALSE / POP_JUMP_IF_TRUE bytecodes. Chained comparisons are compiled as a single expression with two comparisons — atomic and efficient.

13for, while, break, continue, and loop-else

What & why. Python loops iterate over iterables. break exits the innermost loop, continue skips to the next iteration, and the else clause executes only if the loop completed without hitting break.

for char in "Python":
    print(char, end=" ")
print()  # P y t h o n

n = 10
while n > 0:
    n -= 3
print(n)  # -2

for i in range(100):
    if i ** 2 > 50:
        print(f"First square > 50: {i**2}")
        break

for i in range(10):
    if i % 3 == 0:
        continue
    print(i, end=" ")  # 1 2 4 5 7 8

def is_prime(n):
    if n < 2:
        return False
    for i in range(2, int(n ** 0.5) + 1):
        if n % i == 0:
            break
    else:
        return True
    return False

print(is_prime(17))  # True
Where you'll use itLoops are the core of data processing, algorithms, and control flow. The loop-else pattern distinguishes "found and exited" from "never found."
Under the hoodPython's for loop calls __iter__() then repeatedly __next__(), catching StopIteration. The else clause uses a bytecode flag tracking whether break was hit.

14match-case (Structural Pattern Matching)

What & why. Python 3.10 introduced match-case for structural pattern matching — similar to switch-case but far more powerful. It supports value matching, sequence unpacking, mapping patterns, and guard clauses.

def http_status(code):
    match code:
        case 200:
            return "OK"
        case 301:
            return "Moved"
        case 404:
            return "Not Found"
        case _:
            return f"Unknown: {code}"

def process_command(cmd):
    match cmd.split():
        case ["quit"]:
            return "exiting"
        case ["load", filename]:
            return f"loading {filename}"
        case ["move", x, y] if x.isdigit() and y.isdigit():
            return f"moving to ({x}, {y})"
        case _:
            return "unknown command"

def handle_event(event):
    match event:
        case {"type": "click", "x": x, "y": y}:
            return f"Click at ({x}, {y})"
        case {"type": "key", "key": key, "modifiers": mods}:
            return f"Key {key} with {mods}"
        case {"type": event_type}:
            return f"Unhandled: {event_type}"
Where you'll use itPattern matching excels in protocol parsing, AST traversal, event handling, CLI command dispatch, and complex branching over structured data.
Under the hoodThe match statement compiles to comparison bytecodes. The _ wildcard always matches. Guard clauses (if) add runtime boolean checks after the pattern succeeds.

15def Functions

What & why. Functions in Python are first-class objects. The def statement creates a function object with a name, parameters, and a docstring. Default arguments, annotations, and nested functions add powerful composition.

def calculate_discount(price: float, rate: float = 0.1) -> float:
    """Calculate discounted price."""
    return price * (1 - rate)

def append_to(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst

def make_multiplier(factor):
    def multiply(x):
        return x * factor
    return multiply

double = make_multiplier(2)
print(double(5))  # 10

print(calculate_discount.__name__)   # "calculate_discount"

import inspect
sig = inspect.signature(calculate_discount)
print(sig.parameters)
Where you'll use itFunctions are the fundamental building block of all Python programs. They enable testability, reuse, composition, and decorator/callback patterns.
Under the hoodA def statement creates a function object containing the code object, default values (evaluated once at definition time), closure cells, and annotations. Calls use the CALL opcode.

16*args and **kwargs

What & why. The *args and **kwargs syntax enables variadic functions — any number of positional or keyword arguments. Essential for decorators, wrappers, and flexible APIs.

def log_everything(*args, **kwargs):
    print(f"Positional: {args}")
    print(f"Keyword: {kwargs}")

log_everything("hello", 42, level="info", module="auth")

connect(**config, timeout=60)

    return {"name": name, "email": email, "role": role}

def divmod_builtin(x, /, y):
    return divmod(x, y)

def full_signature(pos, /, normal, *args, kw_only=True, **kwargs):
    print(f"{pos=}, {normal=}, {args=}, {kw_only=}, {kwargs=}")
Where you'll use it*args/**kwargs power decorators, factory functions, and flexible APIs. The **kwargs pattern is ubiquitous in Django, Flask, and dataclass constructors.
Under the hoodCPython collects excess positional arguments into a tuple and excess keyword arguments into a dict during CALL setup. The * and / markers control argument kind.

17Lambda Functions

What & why. Lambdas are anonymous single-expression functions. They are limited to a single expression, suitable for short callbacks and key functions. Not more performant than def — their value is conciseness.

square = lambda x: x ** 2
print(square(5))  # 25

students = [("Alice", 92), ("Bob", 85), ("Charlie", 95)]
students.sort(key=lambda s: s[1], reverse=True)

from functools import reduce
nums = [1, 2, 3, 4, 5]
product = reduce(lambda a, b: a * b, nums)  # 120

doubled = list(map(lambda x: x * 2, nums))
odds = list(filter(lambda x: x % 2 != 0, nums))

# Prefer def over lambda for named functions
# BAD:  f = lambda x: x + 1
# GOOD:
def f(x):
    return x + 1

handlers = {
    "add": lambda a, b: a + b,
    "sub": lambda a, b: a - b,
}
print(handlers["add"](3, 4))  # 7
Where you'll use itLambdas shine as sort keys, dictionary dispatch values, and one-off callbacks.
Under the hoodLambdas compile to the same code objects as def. The only difference is __name__ defaults to <lambda> and they cannot contain statements.

18LEGB Scope

What & why. Python resolves names using the LEGB rule: Local, Enclosing, Global, Built-in. This four-layer system determines which variable is referenced at any point.

print(len([1, 2, 3]))  # 'len' found in Built-in scope

module_var = "I am global"

def outer():
    enclosing_var = "I am enclosing"

    def inner():
        local_var = "I am local"
        print(local_var)          # Local
        print(enclosing_var)      # Enclosing
        print(module_var)         # Global
    inner()

outer()

counter = 0
def increment():
    global counter
    counter += 1

def make_counter(start=0):
    count = [start]
    def increment(step=1):
        count[0] += step
        return count[0]
    return increment

c = make_counter()
print(c(), c(), c())  # 1 2 3
Where you'll use itLEGB governs every variable reference. Closures (enclosing scope) power decorators, callbacks, and factory functions.
Under the hoodCPython compiles scopes at definition time. Local variables get fastlocals array slots (LOAD_FAST). Enclosing-scope variables become cell objects.

What & why. Type hints (PEP 484, Python 3.5+) annotate signatures with expected types. They don't enforce at runtime but enable static analysis tools like mypy and Pyright to catch bugs before execution.

def greet(name: str) -> str:
    return f"Hello, {name}"

def find_user(user_id: int) -> dict | None:
    ...

def process(value: int | float | str) -> str:
    return str(value)

from collections.abc import Callable
from typing import TypeVar, Sequence
T = TypeVar("T")
def first(items: Sequence[T]) -> T:
    return items[0]

MAX_SIZE: int = 1024
names: list[str] = []

Where you'll use itType hints are standard in production codebases. They improve IDE autocompletion, enable automated documentation, and prevent entire categories of bugs.
Under the hoodAnnotations are stored in __annotations__ (lazily with from __future__ import annotations). Python ignores them at runtime — enforcement is in external tools.

20String Formatting Deep Dive

What & why. Beyond basic f-strings, Python offers format_map, custom __format__, template strings, and textwrap for advanced formatting needs.

from string import Template
t = Template("$name has $count items")
print(t.substitute(name="Alice", count=5))

class Money:
    def __init__(self, amount, currency="USD"):
        self.amount = amount
        self.currency = currency
    def __format__(self, spec):
        if spec == "":
            return f"{self.amount:.2f} {self.currency}"
        return format(self.amount, spec)

price = Money(49.99, "EUR")
print(f"Price: {price}")      # "Price: 49.99 EUR"
print(f"Price: {price:.0f}")  # "Price: 50 EUR"

import textwrap
code = textwrap.dedent("""\
    def hello():
        print("Hello, World!")
""")
print(textwrap.indent(code, "  "))

data = [("Alice", 95), ("Bob", 87), ("Charlie", 100)]
for name, score in data:
    print(f"{name:<12}{score:>5}")

print(f"{1234567:,}")      # "1,234,567"
print(f"{3.14159:.4f}")    # "3.1416"
Where you'll use itCustom formatting is used in financial displays, scientific notation, CLI table output, and localization systems.
Under the hoodf-strings and format() both call __format__. The format spec mini-language is parsed and passed to __format__. Template uses regex-based $ substitution for safer user-facing templating.

21Comprehensions: List, Dict, Set, Generator

What & why. Comprehensions are concise, expressive loops that build collections in a single expression. They are faster than equivalent for-loops because the iteration happens in C. Generator expressions yield items lazily, consuming minimal memory.

# List comprehension
squares = [x ** 2 for x in range(10) if x % 2 == 0]
# [0, 4, 16, 36, 64]

# Dict comprehension
word_lengths = {w: len(w) for w in ["hello", "world", "python"]}

# Set comprehension
ascii_chars = {ord(c) for c in "abracadabra"}

# Generator expression — lazy evaluation
total = sum(x ** 2 for x in range(1_000_000))

# Nested comprehension
matrix = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
flat = [val for row in matrix for val in row]

# Walrus in comprehension (3.8+)
results = [y for x in range(10) if (y := x ** 2) > 20]

# Generator pipeline
def process_pipeline(data):
    return (
        transform(clean(validate(item)))
        for item in data
        if item is not None
    )
Where you'll use itComprehensions are the Pythonic way to transform, filter, and build collections. They appear in virtually every script.
Under the hoodList comprehensions execute in a dedicated bytecode loop (LIST_APPEND) avoiding repeated .append() lookups. Generator expressions create objects that suspend at each yield point.

22Slicing Mastery

What & why. Python slicing (a[start:stop:step]) works on any sequence. Understanding negative indices, slice assignment, and the slice object enables elegant data manipulation without manual index arithmetic.

s = "Python"[0:3]   # "Pyt"
s = "Python"[:3]    # "Pyt"
s = "Python"[-3:]   # "hon"

s = "abcdefgh"[::2]    # "aceg"

43Dunder Methods: __repr__, __eq__, __lt__, __call__, __getitem__, __len__

class Vector:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def __eq__(self, other):
        if not isinstance(other, Vector):
            return NotImplemented
        return self.x == other.x and self.y == other.y

    def __lt__(self, other):
        return (self.x ** 2 + self.y ** 2) < (other.x ** 2 + other.y ** 2)

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __mul__(self, scalar):
        return Vector(self.x * scalar, self.y * scalar)

    def __abs__(self):
        return (self.x ** 2 + self.y ** 2) ** 0.5

    def __len__(self):
        return 2

    def __getitem__(self, index):
        return (self.x, self.y)[index]

    def __call__(self, factor):
        return Vector(self.x * factor, self.y * factor)

62Idiomatic Design Patterns: Singleton, Factory, Strategy, Observer

What & why. Python implements classic design patterns with Pythonic idioms. Singletons use modules, factories use functions or __init_subclass__, strategies use callables, and observers use callbacks or the blinker library.

# Singleton — Python module is already a singleton
# config.py
_config = None

def get_config():
    global _config
    if _config is None:
        _config = {"debug": False, "db_url": "sqlite:///app.db"}
    return _config

# Factory — function or __init_subclass__
class Shape:
    _registry = {}

    @classmethod
    def register(cls, name, klass):
        cls._registry[name] = klass

    @classmethod
    def create(cls, name, **kwargs):
        return cls._registry[name](**kwargs)

class Circle(Shape):
    def __init__(self, radius):
        self.radius = radius

class Rectangle(Shape):
    def __init__(self, width, height):
        self.width, self.height = width, height

Shape.register("circle", Circle)
Shape.register("rect", Rectangle)
shape = Shape.create("circle", radius=5)

# Strategy — first-class functions
def bubble_sort(data): return sorted(data)
def quick_sort(data): return sorted(data, key=lambda x: x)

def process(data, strategy=sorted):
    return strategy(data)

# Observer — callback pattern
class EventEmitter:
    def __init__(self):
        self._listeners = {}

    def on(self, event, callback):
        self._listeners.setdefault(event, []).append(callback)

    def emit(self, event, *args, **kwargs):
        for cb in self._listeners.get(event, []):
            cb(*args, **kwargs)

emitter = EventEmitter()
emitter.on("data", lambda d: print(f"Received: {d}"))
emitter.emit("data", "hello")
Where you'll use itSingletons for config/driver instances, factories for creating objects from data, strategies for swappable algorithms, observers for event-driven architectures.
Under the hoodPython's first-class functions and dynamic typing make many OOP patterns simpler. Modules are natural singletons. Callables replace strategy interfaces. No abstract factory boilerplate needed.

import re
import time
import signal
from pathlib import Path
from collections import defaultdict, Counter

PATTERNS = {
    "apache": re.compile(
        r'(?P<ip>\S+) \S+ \S+ \[(?P<time>[^\]]+)\] '
        r'"(?P<method>\S+) (?P<path>\S+) \S+" (?P<status>\d+)'
    ),
    "error": re.compile(r'ERROR|CRITICAL|FATAL'),
}

class LogTailer:
    def __init__(self, filepath, poll_interval=1.0):
        self.filepath = Path(filepath)
        self.poll_interval = poll_interval
        self.position = self.filepath.stat().st_size if self.filepath.exists() else 0

    def tail(self):
        while True:
            if not self.filepath.exists():
                time.sleep(self.poll_interval)
                continue
            current_size = self.filepath.stat().st_size
            if current_size < self.position:
                self.position = 0  # file rotated
            with open(self.filepath) as f:
                f.seek(self.position)
                for line in f:
                    yield line.rstrip("\n")
                self.position = f.tell()
            time.sleep(self.poll_interval)

class LogAnalyzer:
    def __init__(self):
        self.error_counts = Counter()
        self.status_counts = Counter()
        self.alerts = []

    def process_line(self, line):
        for name, pattern in PATTERNS.items():
            match = pattern.search(line)
            if match:
                self._handlers.get(name, self._default)(match)
                break

    def _handle_apache(self, match):
        self.status_counts[match.group("status")] += 1

    def _handle_error(self, match):
        self.error_counts["errors"] += 1
        if self.error_counts["errors"] > 100:
            self.alerts.append(f"Error threshold exceeded: {self.error_counts['errors']}")

  7. Generate an HTML profiling report with timing breakdowns and memory peak statistics
  8. Validate output with schema checking and row count assertions
import multiprocessing as mp
import pandas as pd
import tracemalloc
import cProfile
import time
from pathlib import Path

def transform_chunk(chunk):
    """Process a chunk of CSV data."""
    chunk = chunk.dropna(subset=["id"])
    chunk["amount"] = chunk["amount"].astype(float)
    chunk["category"] = chunk["category"].str.lower().str.strip()
    chunk["date"] = pd.to_datetime(chunk["date"])
    chunk["total"] = chunk["amount"] * chunk.get("quantity", 1)
    return chunk

def run_etl(input_path, output_path, workers=4, chunksize=100_000):
    tracemalloc.start()
    start = time.perf_counter()
    profiler = cProfile.Profile()
    profiler.enable()

    chunks = pd.read_csv(input_path, chunksize=chunksize)

    with mp.Pool(workers) as pool:
        results = pool.map(transform_chunk, chunks)

    df = pd.concat(results, ignore_index=True)
    df.to_parquet(output_path, engine="pyarrow", compression="snappy", index=False)

    profiler.disable()
    elapsed = time.perf_counter() - start
    current, peak = tracemalloc.get_traced_memory()
    tracemalloc.stop()

    rows = len(df)
    print(f"Processed {rows:,} rows in {elapsed:.2f}s")
    print(f"Memory: current={current/1e6:.1f}MB, peak={peak/1e6:.1f}MB")
    print(f"Output: {Path(output_path).stat().st_size / 1e6:.1f}MB")
    return df
