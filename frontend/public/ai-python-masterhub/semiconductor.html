Part I · FoundationsTier 1 — what a semiconductor is

1Silicon, Doping and the Transistor

What & why. Silicon is a semiconductor: its conductivity sits between conductor and insulator, and — crucially — it can be precisely modified by doping (adding impurity atoms). The transistor — a tiny voltage-controlled switch — is the atom of all computing. Modern chips pack tens of billions of them.

# Semiconductor basics
#   Pure silicon: 4 valence electrons -> perfect crystal lattice
#   Doping with phosphorus (5 e-) -> n-type (extra electrons)
#   Doping with boron     (3 e-) -> p-type (holes / missing e-)
#   n-p-n junction -> transistor: small voltage controls big current

# MOS transistor (the workhorse)
#   Gate (control) | Insulator (SiO2/HfO2) | Channel (Si)
#   Gate voltage ON  -> channel conducts -> current flows (1)
#   Gate voltage OFF -> channel blocks    -> no current (0)

# Moore's law (empirical, 1965-2020s):
#   transistor count ~doubles every ~2 years
#   -> more compute per mm^2 at similar cost
#   Dennard scaling (voltage ~ size) ended ~2006:
#     power density capped frequency, so cores multiplied
Where you'll use itUnderstanding why chips get faster, hotter, and why "more cores" replaced "higher clock" after ~2006.
Under the hoodA CPU is just an orchestrated army of transistors: registers, ALUs, caches, control logic. Every software performance question bottoms out here.

2How a Chip Is Made: The Fab Flow

What & why. Chips are built by printing layers of patterns onto silicon wafers: deposit, coat with photoresist, expose through a mask (lithography), etch, dope, repeat hundreds of times. A modern chip needs 1,000+ process steps over months.

# Simplified fab flow
# 1. Wafer:   grow ultra-pure silicon ingot, slice into wafers
# 2. Deposit: grow insulating/conducting layers (CVD, PVD)
# 3. Coat:    spin photoresist (light-sensitive polymer)
# 4. Expose:  UV/EUV light through a photomask -> pattern
# 5. Develop: wash away exposed resist
# 6. Etch:    remove material where resist is gone
# 7. Implant: dope exposed regions (ion implantation)
# 8. Repeat   for each of 50-100 mask layers
# 9. Test:    probe wafer, cut dies, package good ones

# Process node naming ("5nm", "3nm", "2nm"):
#   historically = minimum feature size / gate length
#   today = marketing-ish density metric, NOT physical size

# EUV lithography (13.5nm light) enabled 7nm and below;
# it costs ~$150M+ per machine. This is why fabs cost $10B+.
Where you'll use itInterpreting chip announcements and understanding why capacity is geopolitically strategic (TSMC, Samsung, Intel, and the "chip war").
Under the hoodYield (fraction of working dies) drives cost: smaller nodes + more defects = lower yield = expensive chips. Defect density is the real technology scoreboard.

Part II · ArchitectureTier 2 — how computing is organized

3CPU vs GPU vs Accelerator

What & why. CPUs optimize latency on few complex cores; GPUs optimize throughput on thousands of simple cores; AI accelerators (TPU, NPU) specialize further, trading generality for raw matrix speed. AI training = massive parallelism = GPUs/accelerators win.

# Compute model comparison
# CPU:    few cores (8-64), deep pipelines, big caches,
#         branch prediction, out-of-order -> latency-optimal
# GPU:    thousands of ALUs (16k+ on H100), SIMT warps,
#         high memory bandwidth, throughput-optimal
# TPU:    systolic array of matrix multiply units (MXU),
#         no general-purpose cores -> max TFLOPS/W

# Why AI = matrix math
#   attention:   QK^T, softmax, PV   -> dense matmuls
#   MLP:         GEMM after GEMM
#   conv:        implicit GEMM
# Utilization = time in matmul / total time
#   -> measured as MFU (model FLOPs utilization)

# Modern numbers (approx):
#   H100 SXM: ~990 TFLOPS FP16, ~3.35 TB/s HBM3, 700W
#   GB200:    two GPUs + Grace CPU, ~40-45 PFLOPS per rack
Where you'll use itChoosing hardware for training vs inference, and understanding why GPU memory (VRAM) is THE bottleneck for LLM work.
Under the hoodA GPU warps (32 threads) execute one instruction at a time on all lanes — branch divergence serializes. Writing GPU-friendly code means avoiding divergence and maximizing coalesced memory access.

4Memory Hierarchy and HBM

What & why. Memory, not compute, is the real bottleneck: LLM inference streams model weights from memory for every token. High Bandwidth Memory (HBM) stacks DRAM dies with through-silicon vias to deliver terabytes/second — the reason modern AI chips are built around HBM stacks.

# Latency & bandwidth hierarchy (order of magnitude)
#   Register:       ~1 cycle       (bytes)
#   L1 cache:       ~4 cycles      (KB)       10s GB/s
#   L2 cache:       ~15 cycles     (MB)      100s GB/s
#   HBM:            ~100s cycles   (GB)       TB/s
#   GDDR/DRAM:      ~200+ cycles   (GB)       100s GB/s
#   NVMe:           ~100k cycles   (TB)       few GB/s
#   Network:        slower still

# LLM inference bandwidth math
#   weights: 7B params * 2 bytes (fp16) = 14 GB
#   tokens/s  ~ memory_bandwidth / bytes_per_token
#   H100 (3.35 TB/s): ~ 3.35e12 / 14e9 ~ 240 tok/s  (1 stream)
#   -> memory-bound: compute sits idle waiting for weights

# HBM construction:
#   DRAM dies stacked + TSVs (vertical wires) + wide bus
#   H100: 6 stacks HBM3 = 80GB @ 3.35 TB/s
Where you'll use itEstimating inference throughput, choosing KV-cache sizes, and deciding quantization strategy (fewer bits = fewer bytes = faster).
Under the hoodThis is why quantization (see LLMs) speeds inference: 4-bit weights cut bytes per token ~4x, directly multiplying token throughput.

5Advanced Packaging: Chiplets and CoWoS

What & why. Shrinking transistors gets harder and pricier, so the industry assembles chiplets: smaller dies built on different nodes, stitched together on a silicon interposer with ultra-fine wiring (CoWoS). This is how NVIDIA packs GPU + HBM into one package.

# Chiplet design (AMD EPYC, NVIDIA Blackwell, Intel Ponte Vecchio)
#   - one big die  ->  several smaller chiplets
#   - compute chiplets (latest node) + I/O chiplets (cheap node)
#   - connected by interposer or bridge (CoWoS, EMIB)

# CoWoS (Chip-on-Wafer-on-Substrate)
#   chiplets + HBM stacks sit on a silicon interposer
#   interposer provides ultra-dense wiring between dies
#   -> bandwidth between GPU and HBM without PCB traces

# Why chiplets win:
#   - yield: smaller die = more dies per wafer = better yield
#   - flexibility: mix nodes, mix vendors
#   - scale: HBM stacks + compute in ONE package

# Cost reality:
#   CoWoS capacity is a supply-chain bottleneck for AI
#   (every big GPU needs 6-8 HBM stacks + interposer)
Where you'll use itUnderstanding why "AI GPU shortage" is partly a packaging shortage, and why procurement lead times are long.
Under the hoodThe interposer is basically a silicon PCB with micron-scale wiring; its reticle-size limits drive 2.5D designs and the move to co-packaged optics for networking.

Part III · AcceleratorsTier 3 — why AI chips are shaped like this

6Systolic Arrays and the TPU

What & why. A systolic array is a grid of multiply-accumulate (MAC) units where data flows like a heartbeat — each unit computes, then passes partial results to neighbors. It turns matrix multiply into a data-movement problem: nearly 100% of the hardware is doing math, not control.

# Matrix multiply on a systolic array (concept)
# C = A x B ; A rows stream in from top, B columns from left
#
#   B0  B1  B2
# A0 [MAC] [MAC] [MAC]
# A1 [MAC] [MAC] [MAC]   each MAC: c += a * b, pass values on
# A2 [MAC] [MAC] [MAC]
#
# TPU v1: 256x256 systolic array = 65,536 MACs
#   -> ~92 TOPS INT8, 700 mm^2, only ~28 MB SRAM (no HBM v1)
#   - uses SRAM (fast, on-die) because matmul is data-reuse-heavy
#
# MAC count = the headline AI hardware metric
#   H100:    ~989 TFLOPS FP16  (huge tensor cores)
#   B200:    ~2.25 PFLOPS FP16 per die

# Data reuse is the point:
#   each weight used by many inputs -> keep it in SRAM/registers
Where you'll use itUnderstanding why TPUs/NPUs are orders of magnitude more efficient per watt than CPUs for matmul-heavy workloads.
Under the hoodThe "systolic" name: data pulses through the array synchronously like blood through a heart. Control overhead is minimized — the array just multiplies and passes.

7Tensor Cores and Precision Trade-offs

What & why. NVIDIA tensor cores perform 4x4 matrix multiplies in one instruction with mixed precision: inputs at FP16/BF16, accumulation in FP32. Training uses lower precision where safe; inference quantization (INT8/FP8/INT4) trades precision for speed.

# Precision ladder (AI workloads)
#   FP32:   standard float  (training fallback, stable)
#   BF16:   FP32 exponent, FP16 mantissa (training sweet spot)
#   FP16:   half float (training with loss scaling)
#   FP8:    emerging training (2x speed, needs care)
#   INT8:   inference quantization (4x speed vs FP16)
#   INT4:   aggressive quantization (see LLMs chapter)

# Tensor core example (H100):
#   FP16/BF16:  ~990 TFLOPS
#   FP8:        ~1979 TFLOPS (2x)
#   INT8:       ~1980 TOPS
#   FP64:       ~34 TFLOPS  (tiny on purpose - HPC pays extra)

# Why lower precision works:
#   - weights tolerant to rounding (learned redundancy)
#   - 4x fewer bytes = 4x more tokens/s (memory-bound)
#   - rule of thumb: keep BF16 for first training run,
#     quantize for inference after eval passes
Where you'll use itChoosing training dtypes, planning inference hardware, and reading GPU spec sheets correctly (TFLOPS differs by precision!).
Under the hoodFP8 training required new numerics (scaling factors, E4M3/E5M2 formats); BF16 became the standard because it matches FP32's exponent range, avoiding overflow/underflow.

8NPUs and Edge AI Chips

What & why. NPUs (Neural Processing Units) bring acceleration to phones, laptops and data-center CPUs: Apple Neural Engine, Qualcomm Hexagon, Intel/AMD NPUs. They trade peak throughput for power efficiency — the right tool for always-on inference.

# NPU characteristics
#   - small systolic/MAC arrays (TOPS range: 10s-100s)
#   - aggressive INT8/FP16 support, no FP64
#   - ultra-low power: watts, not hundreds of watts
#   - tightly coupled with CPU memory (no HBM)
#   - ONNX/TFLite runtime support via vendor SDKs

# Where NPUs fit:
#   on-device LLM (7B quantized fits in 8GB phone RAM)
#   real-time vision (face unlock, AR)
#   sensor fusion, wake words, background processing
#   privacy: data never leaves the device

# Data-center trend: CPU + NPU (Intel Lunar Lake, AMD Ryzen AI)
#   -> "AI PC" marketing vs real TOPS differences; check
#   sustained throughput, not just peak marketing TOPS
Where you'll use itEdge deployment decisions (see IoT & Edge AI), and evaluating AI-PC/laptop specs for local LLM work.
Under the hoodNPU performance is memory-bound too: phone DRAM bandwidth (~50 GB/s) caps 7B-model tokens/sec, which is why quantization is mandatory on-device.

Part IV · Systems & EDATier 4 — designing and operating chips

9Power, Thermal and Data-Center Reality

What & why. A 700W H100 must be cooled and powered; an 8-GPU node draws ~10kW; a cluster of thousands needs megawatts. Power and thermals — not chip design — often decide what AI you can run.

# Power budget math
#   H100 SXM:  700W per GPU; 8x H100 node ~ 5.6-10 kW
#   1000-GPU cluster: ~5-10 MW + cooling overhead
#   Data center total ~ PUE * IT load (PUE ~1.1-1.4)

# Cooling hierarchy
#   air:     up to ~20-30 kW/rack (traditional)
#   liquid:  direct-to-chip cold plates, ~100+ kW/rack
#   immersion: whole-rack immersion in dielectric fluid
#   -> Blackwell racks push 120+ kW/rack -> liquid required

# Thermal design power (TDP) vs actual:
#   TDP = designed dissipation; throttling kicks in at limits
#   Sustained throughput > peak marketing TFLOPS

# Consequences for engineers:
#   - training runs planned around power availability
#   - inference servers sized by memory bandwidth + power
#   - scheduling = power scheduling in the cloud
Where you'll use itCapacity planning, cloud region selection, and understanding GPU "shortage" news (power + packaging, not just fab).
Under the hoodFrequency throttling is a feedback loop: temperature -> lower clock -> lower FLOPs. Benchmark with sustained loads, not quick runs.

10EDA, RTL and the Design Flow

What & why. Chip design is software: RTL (Verilog/SystemVerilog) describes logic, synthesis converts to gates, place-and-route lays them out, and verification proves correctness — before a single wafer is printed. Design cost for a leading-edge chip exceeds $500M.

// Verilog: a tiny MAC unit at RTL level
module mac #(parameter W = 16) (
    input  logic [W-1:0] a, b,
    input  logic         clk, rst,
    output logic [2*W:0] acc
);
    always_ff @(posedge clk) begin
        if (rst) acc <= 0;
        else     acc <= acc + a * b;
    end
endmodule

# Design flow
#   1. Architecture (spec, microarchitecture)
#   2. RTL design (SystemVerilog)
#   3. Verification (UVM testbenches, formal proof) ~70% effort
#   4. Synthesis (RTL -> gates)
#   5. Place & route (gates -> layout on silicon)
#   6. Timing/power closure (meet clock & power targets)
#   7. Tape-out -> fab -> test -> package -> ship

# AI in EDA (real and growing):
#   - ML-guided placement/routing
#   - reinforcement learning for macro placement (Google)
#   - ML-based verification coverage, defect detection
Where you'll use itUnderstanding why chips take 2-3+ years and why EDA (Synopsys, Cadence, Siemens) is a trillion-dollar industry keystone.
Under the hoodVerification consumes most of design time because a bug found after tape-out costs millions — hence "verification is the product."

11Sparse Compute and Future Architectures

What & why. Many weights are near-zero (pruning) and attention is sparse. Sparse accelerators skip zero MACs for 2x-4x speedups; the frontier is 2-bit/ternary weights, analog/in-memory compute, optical interconnect, and post-silicon devices.

# Sparsity in practice
#   - 2:4 structured sparsity (NVIDIA): in every 4 weights,
#     at least 2 are zero -> tensor cores skip them
#   - unstructured pruning + sparse kernels (deepsparse)
#   - attention sparsity: only attend to relevant tokens
#     (sliding window, cross-attention selection)

# Future directions
#   - In-memory computing: matmul in memory (compute-in-SRAM)
#   - Analog compute: current summing for dot products
#   - Photonics: optical interconnects / co-packaged optics
#   - 2-bit / ternary weight models (research, promising)
#   - Neuromorphic: event-driven spiking chips (Loihi)

# Engineer takeaway:
#   sparsity-aware kernels + quantization + caching
#   usually beat waiting for new hardware
Where you'll use itOptimizing inference (sparse kernels), and horizon-scanning for the "next H100" wave.
Under the hood2:4 structured sparsity is hardware-accelerated (no branches): the array fetches compressed 2-of-4 blocks and the MACs that would be zero are simply not issued.

Part V · ProjectsTier 5 — program the hardware

12Project 1 — CUDA Kernel: Matrix Multiply

What & why. Write a GEMM with tiling in CUDA, then measure it against cuBLAS. You will feel the memory-hierarchy lesson: tiling to shared memory is where the 10x speedup lives.

// Tiled matrix multiply kernel (16x16 tiles)
__global__ void gemm_tiled(const float* A, const float* B,
                           float* C, int N) {
    __shared__ float As[16][16], Bs[16][16];
    int row = blockIdx.y*16 + threadIdx.y;
    int col = blockIdx.x*16 + threadIdx.x;
    float acc = 0.0f;

    for (int t = 0; t < (N + 15)/16; t++) {
        // cooperative load tile into shared memory
        As[threadIdx.y][threadIdx.x] =
            A[row*N + t*16 + threadIdx.x];
        Bs[threadIdx.y][threadIdx.x] =
            B[(t*16 + threadIdx.y)*N + col];
        __syncthreads();
        for (int k = 0; k < 16; k++)
            acc += As[threadIdx.y][k] * Bs[k][threadIdx.x];
        __syncthreads();
    }
    C[row*N + col] = acc;
}

# Compare: naive (no tiling) vs tiled vs cuBLAS
# Expect: tiled ~5-20x over naive; cuBLAS still 2-5x faster
# because it uses tensor cores + autotuning. Run with nvprof
# or Nsight Compute and watch memory throughput vs compute.

14Project 3 — Model-to-Chip Cost Model

What & why. Build a spreadsheet-style cost model that takes a model (params, dtype, batch, seq len) and a GPU (bandwidth, FLOPs, price) and returns tokens/sec, cost per million tokens, and utilization — the numbers every AI team actually negotiates.

def cost_model(params_b, dtype_bits, batch, seq_len,
               bandwidth_tbs, price_usd, utilization=0.6):
    bytes_per_token = params_b * 1e9 * dtype_bits / 8
    # KV cache adds seq_len * layers * dims * 2 * bytes
    compute_per_token = 2 * params_b * 1e9  # ~2 FLOPs/param

    tokens_s = bandwidth_tbs * 1e12 * utilization / bytes_per_token
    tokens_per_hour = tokens_s * 3600
    cost_per_1m = price_usd / (tokens_per_hour / 1e6)
    return {"tokens_s": round(tokens_s),
            "cost_per_1m": round(cost_per_1m, 2)}

print(cost_model(params_b=7, dtype_bits=16, batch=1, seq_len=2048,
                 bandwidth_tbs=3.35, price_usd=2.5))
# {'tokens_s': ~86, 'cost_per_1m': ~0.81}  (single stream, util .6)
