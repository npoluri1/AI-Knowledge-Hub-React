1Virtual DOM Concept

What & why. The Virtual DOM is a lightweight JavaScript representation of the real DOM. React diffs the VDOM against the previous version to compute minimal DOM mutations, avoiding expensive full-page repaints. This gives you a declarative programming model with high performance.

// Declarative: describe what the UI should look like
function Counter({ initialCount }) {
  const [count, setCount] = React.useState(initialCount);
  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}
// React computes the diff and updates only the changed text node
Where you'll use itEvery React component uses the VDOM concept. You write components returning JSX, and React efficiently updates the real DOM.
Under the hoodReact 18 uses Fiber for incremental rendering. The VDOM diffing uses heuristics: same-type elements update attributes; different types replace subtrees; keys optimize list reordering.

2JSX Rules

What & why. JSX is a syntax extension compiling to React.createElement() calls. It lets you write HTML-like structures in JavaScript with type safety and expression interpolation.

// Must return a single root element (fragments for multiple)
function UserCard({ name, role }) {
  return (
    <>
      <h2>{name}</h2>
      <p>Role: {role}</p>
    </>
  );
}
// className instead of class, htmlFor instead of for
// Self-closing tags required: <img />, <input />
// Expressions in curly braces: {count + 1}
// Inline styles: style={{ color: 'red' }}
Where you'll use itJSX is the foundation of every React component.
Under the hoodBabel transforms JSX into React.createElement(type, props, ...children) calls. The new JSX transform (React 17+) auto-imports React.

3Components and Props

What & why. Components are reusable, self-contained UI pieces that receive data via props (read-only). Props flow one way: parent to child, making data flow predictable.

function ProductCard({ name, price, inStock = true }) {
  return (
    <div className="product-card">
      <h3>{name}</h3>
      <p>${price.toFixed(2)}</p>
      {!inStock && <span className="badge">Out of Stock</span>}
    </div>
  );
}

function ProductList() {
  const products = [
    { id: 1, name: 'Widget', price: 9.99, inStock: true },
    { id: 2, name: 'Gadget', price: 24.99, inStock: false },
  ];
  return (
    <div>
      {products.map(p => (
        <ProductCard key={p.id} name={p.name} price={p.price} inStock={p.inStock} />
      ))}
    </div>
  );
}
Where you'll use itEvery UI is built from composable components receiving data through props.
Under the hoodProps are shallow-frozen. When a parent re-renders, all children re-render unless wrapped in React.memo.

4Lists and Keys

What & why. Keys help React identify which items have changed, been added, or removed. Without stable keys, React cannot optimize reordering.

function TodoList({ items }) {
  return (
    <ul>
      {items.map(item => (
        <li key={item.id}>
          <input type="checkbox" checked={item.done} />
          {item.text}
        </li>
      ))}
    </ul>
  );
}
// BAD: index keys break on reorder
// GOOD: stable unique IDs from database
Where you'll use itEvery list rendering requires stable keys. Database IDs, UUIDs, or slugs are ideal.
Under the hoodReact's reconciliation matches old and new children by key. New keys create components; missing keys remove them. This enables O(n) list diffing.

5Conditional Rendering

What & why. React provides multiple patterns for conditionally rendering elements: ternaries, logical AND, early returns, and variable assignment.

function Dashboard({ user, notifications, isAdmin }) {
  const greeting = user ? `Hello, ${user.name}` : 'Hello, Guest';
  return (
    <div>
      <h1>{greeting}</h1>
      {notifications.length > 0 && (
        <div>{notifications.length} new notifications</div>
      )}
      {isAdmin ? <AdminPanel /> : <UserPanel />}

Where you'll use itEvery component uses conditional rendering for loading states, error messages, and role-based UI.
Under the hoodExpressions returning null/undefined render nothing. Logical AND short-circuits. Ternary always renders one of two branches.

6Event Handling

What & why. React uses SyntheticEvents wrapping native DOM events for cross-browser consistency. Event handlers are passed as camelCase props.

function SearchForm({ onSearch }) {
  function handleSubmit(e) {
    e.preventDefault();
    const formData = new FormData(e.target);
    onSearch(formData.get('query'));
  }
  function handleKeyDown(e) {
    if (e.key === 'Escape') {
      e.target.value = '';
      onSearch('');
    }
  }
  return (
    <form onSubmit={handleSubmit}>
      <input name="query" type="search" onKeyDown={handleKeyDown} />
      <button type="submit">Search</button>
    </form>
  );
}
Where you'll use itForms, buttons, keyboard shortcuts, and drag-and-drop all use event handling.
Under the hoodReact attaches event listeners to the root node via event delegation. SyntheticEvents normalize cross-browser differences.

7useState Hook

What & why. useState declares a state variable and setter. When the setter is called, React re-renders the component. State updates are batched and asynchronous.

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  const [user, setUser] = useState({ name: '', role: 'user' });

  // Functional update (always correct for prev-dependent updates)
  const safeIncrement = () => setCount(prev => prev + 1);

  // Object state: spread to avoid mutation
  const updateName = (name) => setUser(prev => ({ ...prev, name }));

  // Lazy initialization
  const [data] = useState(() =>
    JSON.parse(localStorage.getItem('data')) ?? []
  );

  return <div><p>Count: {count}</p><button onClick={safeIncrement}>+1</button></div>;
}
Where you'll use itEvery component with interactive state uses useState.
Under the hoodReact 18 batches all state updates. The functional update form ensures correctness with multiple prev-dependent updates.

8Controlled Forms

What & why. Controlled forms bind input values to React state, giving full control over every keystroke for real-time validation and formatting.

import { useState } from 'react';

function ContactForm() {
  const [form, setForm] = useState({ name: '', email: '', message: '' });
  const [errors, setErrors] = useState({});

  function handleChange(e) {
    const { name, value } = e.target;
    setForm(prev => ({ ...prev, [name]: value }));
    if (errors[name]) setErrors(prev => ({ ...prev, [name]: null }));
  }

  function handleSubmit(e) {
    e.preventDefault();
    const errs = {};
    if (!form.name.trim()) errs.name = 'Name is required';
    if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(form.email)) errs.email = 'Invalid email';
    if (Object.keys(errs).length) { setErrors(errs); return; }
    console.log('Submitting:', form);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input name="name" value={form.name} onChange={handleChange} />
      {errors.name && <span>{errors.name}</span>}
      <input name="email" value={form.email} onChange={handleChange} />
      <button type="submit">Send</button>
    </form>
  );
}
Where you'll use itEvery form in React should be controlled for predictable state management.
Under the hoodControlled inputs trigger a re-render on every keystroke. For performance-critical inputs, consider react-hook-form.

9useEffect Introduction

What & why. useEffect handles side effects: data fetching, subscriptions, timers. It runs after render with a dependency array controlling when it re-runs.

import { useState, useEffect } from 'react';

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let cancelled = false;
    setLoading(true);
    fetch(`/api/users/${userId}`)
      .then(r => r.json())
      .then(data => { if (!cancelled) { setUser(data); setLoading(false); } });
    return () => { cancelled = true; };  // Cleanup
  }, [userId]);  // Re-run only when userId changes

  useEffect(() => {
    document.title = 'User Profile';
    return () => { document.title = 'My App'; };
  }, []);  // Empty deps: runs once on mount

  if (loading) return <p>Loading...</p>;
  return <h1>{user?.name}</h1>;
}
Where you'll use ituseEffect handles data fetching, subscriptions, and document title updates.
Under the hoodEffects run after browser paint. The cleanup function prevents stale updates. React compares deps by Object.is.

12Lifting State

What & why. When two components need shared state, lift it to their closest common ancestor. The parent owns state and passes it down via props with callbacks.

function TemperatureConverter() {
  const [temp, setTemp] = useState('');
  const [scale, setScale] = useState('celsius');

  const celsius = scale === 'fahrenheit'
    ? (parseFloat(temp) - 32) * 5 / 9 : parseFloat(temp);
  const fahrenheit = scale === 'celsius'
    ? parseFloat(temp) * 9 / 5 + 32 : parseFloat(temp);

  return (
    <div>
      <TemperatureInput scale="celsius"
        value={isNaN(celsius) ? '' : celsius.toFixed(1)}
        onChange={(v) => { setTemp(v); setScale('celsius'); }} />
      <TemperatureInput scale="fahrenheit"
        value={isNaN(fahrenheit) ? '' : fahrenheit.toFixed(1)}
        onChange={(v) => { setTemp(v); setScale('fahrenheit'); }} />
    </div>
  );
}

function TemperatureInput({ scale, value, onChange }) {
  return (
    <fieldset>
      <legend>{scale}</legend>
      <input type="number" value={value}
        onChange={(e) => onChange(e.target.value)} />
    </fieldset>
  );
}
Where you'll use itAny time sibling components need to share data: linked form fields, filter + display panels.
Under the hoodLifting state is the simplest sharing pattern. For deeper sharing, use Context or state management libraries.

13useRef for Mutable References

What & why. useRef creates a mutable container whose .current persists across renders without triggering re-renders. Used for DOM access, storing previous values, and holding non-render-triggering values.

import { useRef, useEffect } from 'react';

function AutoFocusInput() {
  const inputRef = useRef(null);
  const renderCount = useRef(0);
  useEffect(() => { inputRef.current?.focus(); }, []);
  renderCount.current += 1;
  return (
    <div>
      <input ref={inputRef} placeholder="Auto-focused" />
      <p>Rendered {renderCount.current} times</p>
    </div>
  );
}

// Storing previous value
function usePrevious(value) {
  const ref = useRef();
  useEffect(() => { ref.current = value; });
  return ref.current;
}
Where you'll use itDOM refs for focus management, measuring dimensions, storing timeout IDs.
Under the hooduseRef returns the same object across renders. Mutating .current doesn't trigger re-renders.

14useReducer for Complex State

What & why. useReducer externalizes state transitions into a reducer function, making complex state logic testable and predictable.

import { useReducer } from 'react';

function cartReducer(state, action) {
  switch (action.type) {
    case 'ADD_ITEM': return { ...state, items: [...state.items, action.payload] };
    case 'REMOVE_ITEM':
      return { ...state, items: state.items.filter(i => i.id !== action.payload) };
    case 'CLEAR_CART': return { ...state, items: [] };
    default: throw new Error(`Unknown action: ${action.type}`);
  }
}

function ShoppingCart() {
  const [state, dispatch] = useReducer(cartReducer, { items: [] });
  const total = state.items.reduce((sum, i) => sum + i.price, 0);
  return (
    <div>
      <p>{state.items.length} items — ${total}</p>
      <button onClick={() => dispatch({ type: 'ADD_ITEM', payload: { id: 1, price: 9.99 } })}>Add</button>
      <button onClick={() => dispatch({ type: 'CLEAR_CART' })}>Clear</button>
    </div>
  );
}
Where you'll use itShopping carts, multi-step forms, undo/redo systems, and related state transitions.
Under the hooduseReducer is built on useState. Reducers must be pure functions with no side effects.

15useContext for Global State

What & why. useContext reads values from React Context without prop drilling. Combined with useReducer, it creates a lightweight global state store.

import { createContext, useContext, useState, useMemo } from 'react';

const AuthContext = createContext(null);

function AuthProvider({ children }) {
  const [user, setUser] = useState(null);
  const value = useMemo(() => ({
    user,
    login: (credentials) => setUser({ name: credentials.name }),
    logout: () => setUser(null),
    isAuthenticated: !!user,
  }), [user]);
  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

function useAuth() {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be within AuthProvider');
  return ctx;
}

function Navbar() {
  const { user, logout, isAuthenticated } = useAuth();
  return (
    <nav>
      {isAuthenticated
        ? <><span>{user.name}</span><button onClick={logout}>Logout</button></>
        : <a href="/login">Login</a>}
    </nav>
  );
}
Where you'll use itAuth state, theme preferences, locale, and feature flags.
Under the hoodContext re-renders all consumers when value changes. useMemo prevents unnecessary re-renders.

16Custom Hooks

What & why. Custom hooks extract reusable stateful logic. They follow the use* convention and can call other hooks.

import { useState, useEffect } from 'react';

function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);
  useEffect(() => {
    let cancelled = false;
    setLoading(true);
    fetch(url).then(r => { if (!r.ok) throw new Error(`HTTP ${r.status}`); return r.json(); })
      .then(data => { if (!cancelled) { setData(data); setLoading(false); } })
      .catch(err => { if (!cancelled) { setError(err); setLoading(false); } });
    return () => { cancelled = true; };
  }, [url]);
  return { data, loading, error };
}

function useDebounce(value, delay = 300) {
  const [debounced, setDebounced] = useState(value);
  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delay);
    return () => clearTimeout(timer);
  }, [value, delay]);
  return debounced;
}

// Usage
function UserSearch() {
  const [query, setQuery] = useState('');
  const debouncedQuery = useDebounce(query);
  const { data, loading } = useFetch(`/api/search?q=${debouncedQuery}`);
  return (
    <div>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      {loading ? <p>Searching...</p> : <pre>{JSON.stringify(data)}</pre>}
    </div>
  );
}
Where you'll use ituseFetch, useDebounce, useLocalStorage, useMediaQuery are reusable custom hooks.
Under the hoodCustom hooks are functions calling built-in hooks. Hooks must not be called conditionally.

17Effect Dependencies and Cleanup

What & why. Incorrect dependencies cause stale closures, infinite re-renders, and memory leaks. Every external value used in an effect must be in the dependency array.

import { useState, useEffect } from 'react';

function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);
  useEffect(() => {
    function handleOnline() { setIsOnline(true); }
    function handleOffline() { setIsOnline(false); }
    window.addEventListener('online', handleOnline);
    window.addEventListener('offline', handleOffline);
    return () => {
      window.removeEventListener('online', handleOnline);
      window.removeEventListener('offline', handleOffline);
    };
  }, []);  // Empty deps: listeners don't change
  return isOnline;
}

// Correct timer with functional update
function useTimer(interval) {
  const [count, setCount] = useState(0);
  useEffect(() => {
    const id = setInterval(() => setCount(c => c + 1), interval);
    return () => clearInterval(id);
  }, [interval]);
  return count;
}
Where you'll use itEvery useEffect must have correct deps (exhaustive-deps ESLint rule) and cleanup.
Under the hoodReact compares deps using Object.is for each element. If changed, old effect is cleaned up and new effect runs.

18useMemo and useCallback

What & why. useMemo caches expensive computations; useCallback caches function references. Both prevent unnecessary work when children are memoized.

import { useState, useMemo, useCallback } from 'react';

function FilteredList({ data }) {
  const [filter, setFilter] = useState('');
  const [selected, setSelected] = useState(null);

  const filtered = useMemo(() =>
    data.filter(item =>
      item.name.toLowerCase().includes(filter.toLowerCase())
    ), [data, filter]);

  const handleSelect = useCallback((id) => {
    setSelected(id);
  }, []);

  return (
    <div>
      <input value={filter} onChange={e => setFilter(e.target.value)} />
      <ExpensiveList items={filtered} onSelect={handleSelect} />
    </div>
  );
}
Where you'll use ituseMemo for expensive computations. useCallback for callbacks passed to memoized children.
Under the hooduseMemo stores [deps, value] tuple. useCallback(fn, deps) is equivalent to useMemo(() => fn, deps). Only use when profiling shows a bottleneck.

19Error Boundaries

What & why. Error boundaries catch JavaScript errors in child components, display fallback UI, and prevent full app crashes. They only catch rendering-phase errors.

import { Component } from 'react';

class ErrorBoundary extends Component {
  constructor(props) {
    super(props);
    this.state = { hasError: false, error: null };
  }
  static getDerivedStateFromError(error) {
    return { hasError: true, error };
  }
  componentDidCatch(error, info) {
    console.error('ErrorBoundary caught:', error, info.componentStack);
  }
  render() {
    if (this.state.hasError) {
      return (
        <div className="error-fallback">
          <h2>Something went wrong</h2>
          <p>{this.state.error?.message}</p>
          <button onClick={() => this.setState({ hasError: false })}>Try again</button>
        </div>
      );
    }
    return this.props.children;
  }
}

function App() {
  return <ErrorBoundary><Dashboard /></ErrorBoundary>;
}
Where you'll use itWrap critical UI sections: route-level boundaries for page isolation, widget boundaries for dashboards.
Under the hoodError boundaries catch errors in rendering, lifecycle methods, and constructors. They don't catch event handler or async errors.

20Fragments, Portals, and TypeScript Props

What & why. Fragments group elements without DOM nodes. Portals render into different DOM nodes. TypeScript provides compile-time type safety for component interfaces.

function Modal({ isOpen, onClose, children }) {

    <div className="modal-overlay" onClick={onClose}>

21Fetch Loading and Error Patterns

22TanStack Query Basics

import { QueryClient, QueryClientProvider, useQuery } from '@tanstack/react-query';

const queryClient = new QueryClient({

function UserDashboard() {

24Fiber Architecture Overview

What & why. React Fiber is the reconciliation engine enabling concurrent rendering. It breaks work into small units that can be paused, keeping the UI responsive.

// Two phases:
// 1. Render phase (can be paused): builds fiber tree, computes effects
// 2. Commit phase (synchronous): applies DOM mutations

// Fiber node: stateNode, child/sibling/return pointers,

28Reducer State Machines

What & why. State machines formalize component states as explicit states and transitions, preventing impossible state combinations.

import { useReducer } from 'react';

const transitions = {
  idle: { SUBMIT: 'submitting' },
  submitting: { SUCCESS: 'success', ERROR: 'error' },
  success: { RESET: 'idle' },
  error: { RETRY: 'submitting', RESET: 'idle' },
};

function formReducer(state, action) {
  const next = transitions[state.status]?.[action.type];
  if (!next) return state;
  return { ...state, status: next,
    ...(action.type === 'SUCCESS' && { data: action.payload }),
    ...(action.type === 'ERROR' && { error: action.payload }),
  };
}

function SubmitForm() {
  const [state, dispatch] = useReducer(formReducer, { status: 'idle', data: null, error: null });
  async function handleSubmit() {
    dispatch({ type: 'SUBMIT' });
    try {
      const result = await api.submit();
      dispatch({ type: 'SUCCESS', payload: result });
    } catch (err) {
      dispatch({ type: 'ERROR', payload: err.message });
    }
  }
  return (
    <div>
      <button onClick={handleSubmit} disabled={state.status === 'submitting'}>
        {state.status === 'submitting' ? 'Saving...' : 'Submit'}
      </button>
      {state.status === 'error' && <p>Error: {state.error}</p>}
    </div>
  );
}
Where you'll use itMulti-step forms, payment flows, and UIs with clear states (idle/loading/success/error).
Under the hoodState machines eliminate impossible combinations. The transitions table is data-driven and easy to test.

32Render vs Commit Phases

What & why. React's pipeline has two phases: render (pure computation, can be interrupted) and commit (synchronous DOM mutation). Understanding this explains useEffect timing and concurrent behavior.

function Component() {
  const computed = useMemo(() => expensiveCalc(data), [data]);

  // Runs after commit (pre-paint) - synchronous DOM reads
  useLayoutEffect(() => {
    const height = ref.current.offsetHeight;
    setHeight(height);
  }, []);

  // Runs after paint - safe for subscriptions
  useEffect(() => {
    const unsub = api.subscribe(handleEvent);
    return unsub;
  }, []);

  return <div ref={ref}>{computed}</div>;
}
Where you'll use itUnderstanding phases explains why useEffect is async, useLayoutEffect is sync, and side effects in render cause bugs.
Under the hoodThe render phase calls components and runs hooks. The commit phase applies effects: useLayoutEffect, DOM mutations, then useEffect (post-paint).

37Optimistic Updates

What & why. Optimistic updates immediately reflect changes before server confirmation, rolling back on failure. This makes apps feel instant.

import { useMutation, useQueryClient } from '@tanstack/react-query';

function LikeButton({ postId, isLiked }) {
  const queryClient = useQueryClient();
  const mutation = useMutation({
    mutationFn: () => fetch(`/api/posts/${postId}/like`, { method: 'POST' }),
    onMutate: async () => {
      await queryClient.cancelQueries({ queryKey: ['post', postId] });
      const previous = queryClient.getQueryData(['post', postId]);
      queryClient.setQueryData(['post', postId], old => ({
        ...old, likes: old.likes + (isLiked ? -1 : 1), isLiked: !isLiked,
      }));
      return { previous };
    },
    onError: (err, vars, context) => {
      queryClient.setQueryData(['post', postId], context.previous);
    },
    onSettled: () => queryClient.invalidateQueries({ queryKey: ['post', postId] }),
  });
  return <button onClick={() => mutation.mutate()}>{isLiked ? 'Unlike' : 'Like'}</button>;
}
Where you'll use itLikes, bookmarks, follow/unfollow, and task completion where success rate is high.
Under the hoodonMutate captures current state for rollback. onError rolls back; onSettled refetches for consistency.

38WebSocket Hook and React 19 Patterns

What & why. A custom WebSocket hook encapsulates connection lifecycle. React 19 introduces useOptimistic for simplified async state transitions.

import { useState, useEffect, useRef, useCallback } from 'react';

function useWebSocket(url) {
  const [messages, setMessages] = useState([]);
  const [connected, setConnected] = useState(false);
  const wsRef = useRef(null);

  useEffect(() => {
    const ws = new WebSocket(url);
    wsRef.current = ws;
    ws.onopen = () => setConnected(true);
    ws.onclose = () => {
      setConnected(false);
      setTimeout(() => { wsRef.current = new WebSocket(url); }, 3000);
    };
    ws.onmessage = (e) => setMessages(prev => [...prev, JSON.parse(e.data)]);
    return () => ws.close();
  }, [url]);

  const send = useCallback((data) => wsRef.current?.send(JSON.stringify(data)), []);
  return { messages, connected, send };
}
