47Next-Token Prediction: The Core Objective

What & why. Every autoregressive language model is trained on a single objective: given all previous tokens, predict the probability distribution over the next token. Text generation is simply sampling from this distribution repeatedly. The model outputs logits (raw scores) for every token in its vocabulary, converted to probabilities via softmax.

import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained("gpt2")
model = AutoModelForCausalLM.from_pretrained("gpt2")

input_ids = tokenizer.encode("The capital of France is", return_tensors="pt")
with torch.no_grad():
    outputs = model(input_ids)
    logits = outputs.logits[:, -1, :]
    probs = torch.softmax(logits, dim=-1)
    top_k = torch.topk(probs, k=5)
    for prob, token in zip(top_k.values[0], top_k.indices[0]):
        print(f"  {tokenizer.decode(token):>12}: {prob:.4f}")
Where you'll use itUnderstanding next-token prediction is essential for controlling generation quality, debugging unexpected outputs, and designing prompts that guide the model toward desired continuations.
Under the hoodThe model computes attention over all previous tokens to produce a hidden state for the last position, projected to vocabulary-size logits. The softmax converts these to a probability distribution. Generation quality depends on how well this distribution captures the desired continuation.

Additional Example — Batched next-token prediction with logits manipulation:

import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

tokenizer = AutoTokenizer.from_pretrained("gpt2")
model = AutoModelForCausalLM.from_pretrained("gpt2")

# Batched prediction: multiple prompts at once
prompts = ["The capital of France is", "The capital of Japan is", "The capital of Brazil is"]
inputs = tokenizer(prompts, return_tensors="pt", padding=True)

with torch.no_grad():
    outputs = model(**inputs)
    logits = outputs.logits[:, -1, :]  # last token logits

# Apply top-k masking manually
for i, prompt in enumerate(prompts):
    k = 5
    values, indices = torch.topk(logits[i], k)
    print(f"\nPrompt: '{prompt}'")
    for v, idx in zip(values, indices):
        token = tokenizer.decode(idx)
        prob = torch.softmax(logits[i], dim=-1)[idx].item()
        print(f"  {token:>15}: {prob:.4f} (logit={v:.2f})")

# Why this matters: logit magnitudes indicate confidence
# A spread of 1.0+ between top tokens means high confidence
# A flat distribution means the model is uncertain
Real-World Use CaseNext-token prediction is the engine behind autocomplete in search engines, code completion tools (GitHub Copilot, TabNine), and smart keyboard suggestions. Google's search suggestions use a similar probabilistic next-token model to predict what you're typing and offer completions in real-time. When you type "how to make a" and see suggestions, that's next-token prediction at work.
Internal Behavior Deep-DiveThe forward pass works in stages: (1) Embedding layer maps token IDs to dense vectors. (2) Positional encoding adds position information. (3) Each transformer block applies self-attention (tokens look at each other) then FFN (tokens process what they learned). (4) Final layer norm stabilizes. (5) Linear projection maps hidden state to vocabulary logits. The entire stack runs in one pass — the model processes all input tokens simultaneously, not sequentially. Only during generation do we decode one token at a time.

48BPE Tokenization with tiktoken

What & why. Byte-Pair Encoding (BPE) tokenizes text by iteratively merging the most frequent byte pairs. It converts text to integer tokens that the model processes. tiktoken is OpenAI's fast BPE implementation. Token count directly affects cost, context window usage, and output quality for non-English text.

import tiktoken

enc = tiktoken.get_encoding("cl100k_base")

text = "Embeddings convert text to vectors for semantic search"
tokens = enc.encode(text)
print(f"Tokens: {tokens}")
print(f"Decoded: {[enc.decode([t]) for t in tokens]}")
print(f"Token count: {len(tokens)}")

cost_per_1k = 0.0005
total_cost = (len(tokens) / 1000) * cost_per_1k
print(f"Cost for this text: ${total_cost:.6f}")

cn_text = "嵌入是向量表示"
cn_tokens = enc.encode(cn_text)
print(f"Chinese chars: {len(cn_text)}, tokens: {len(cn_tokens)}")
Where you'll use itToken counting is required for cost estimation, context window management, and prompt optimization. tiktoken is used in production for accurate token accounting before sending to OpenAI APIs.
Under the hoodBPE starts with individual bytes and iteratively merges the most frequent pair until the desired vocabulary size is reached. This gives a good balance between character-level and word-level tokenization.

Real-World Use CaseTokenization directly affects billing in production. Internal Behavior Deep-DiveBPE works by: (1) Splitting text into individual bytes. (2) Counting frequency of every adjacent byte pair across the training corpus. (3) Merging the most frequent pair into a new token. (4) Repeating until vocabulary reaches target size (e.g., 100K for cl100k_base). The result: common words become single tokens, rare words split into subword pieces, and unknown characters fall back to byte-level representation. This is why "the" is one token but "antidisestablishmentarianism" splits into multiple.

49Context Window Limits and Management

What & why. The context window is the maximum number of tokens a model can process in a single forward pass. GPT-4 supports 128K tokens, Claude 3 supports 200K, and local models typically support 4K-32K. Exceeding the limit causes truncation. Effective context management prioritizes recent messages and summarizes older context.

import tiktoken

enc = tiktoken.get_encoding("cl100k_base")

def count_tokens(text: str) -> int:
    return len(enc.encode(text))

def fit_to_context(messages: list[dict], max_tokens: int = 128000) -> list[dict]:
    system = messages[0] if messages[0]["role"] == "system" else None
    rest = messages[1:] if system else messages

    total = count_tokens(system["content"]) if system else 0
    result = [system] if system else []

    for msg in reversed(rest):
        msg_tokens = count_tokens(msg["content"])
        if total + msg_tokens > max_tokens:
            break
        result.insert(1, msg)
        total += msg_tokens

    return result
Where you'll use itContext management is essential for chatbots with conversation history, RAG systems that inject retrieved documents, and long-document analysis tools.
Under the hoodThe context window determines the KV cache size during inference. Longer contexts require more VRAM (quadratic for attention, linear for KV cache) and increase latency proportionally.

Additional Example — Smart context compression and sliding window:

import tiktoken

enc = tiktoken.get_encoding("cl100k_base")

def sliding_window_context(messages: list[dict], max_tokens: int = 8000) -> list[dict]:
    """Keep system prompt + most recent messages within token budget."""
    system = [m for m in messages if m["role"] == "system"]
    rest = [m for m in messages if m["role"] != "system"]
    system_tokens = sum(len(enc.encode(m["content"])) for m in system)
    budget = max_tokens - system_tokens

    selected = []
    for msg in reversed(rest):
        msg_tokens = len(enc.encode(msg["content"]))
        if budget - msg_tokens < 0:
            break
        selected.insert(0, msg)
        budget -= msg_tokens

    return system + selected

def summarize_old_context(messages: list[dict], keep_recent: int = 10) -> list[dict]:
    """Summarize older messages, keep recent ones intact."""
    if len(messages) <= keep_recent:
        return messages
    old = messages[:-keep_recent]
    recent = messages[-keep_recent:]
    summary = f"[Conversation summary: {len(old)} previous messages about various topics]"
    return [{"role": "system", "content": summary}] + recent

# Token budget visualization
def show_token_usage(messages, max_tokens=128000):
    total = sum(len(enc.encode(m["content"])) for m in messages)
    pct = (total / max_tokens) * 100
    bar = "█" * int(pct / 2) + "░" * (50 - int(pct / 2))
    print(f"Context: [{bar}] {pct:.1f}% ({total}/{max_tokens} tokens)")
    if pct > 80:
        print("⚠️  WARNING: Approaching context limit. Consider summarizing.")

messages = [
    {"role": "system", "content": "You are a helpful assistant."},
    {"role": "user", "content": "Tell me about transformers."},
]
show_token_usage(messages)
Real-World Use CaseCustomer support chatbots must manage growing conversation histories. Intercom and Zendesk AI assistants use sliding window strategies to keep the last 10-20 messages in context while summarizing earlier exchanges. Without this, long conversations would exceed token limits, causing truncation of critical early information.
Internal Behavior Deep-DiveThe attention mechanism computes O(n²) operations where n = context length. Doubling context length quadruples attention computation. The KV cache grows linearly: for a 70B model with 80 layers, 64 heads, and 128K context, KV cache alone uses ~40GB. This is why "128K context" models often degrade in quality beyond 32K — the model was trained on shorter sequences and attention patterns weaken.

51Temperature and Sampling Controls

What & why. Temperature scales logits before softmax, controlling randomness: low temperature (0-0.3) produces near-deterministic output; high temperature (0.7-1.5) increases diversity. top_p (nucleus sampling) limits tokens to those whose cumulative probability exceeds p. top_k limits to the k most probable tokens.

from openai import OpenAI

client = OpenAI()

# Deterministic: code generation, factual queries
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Write a Python function to sort a list"}],
    temperature=0.0,
    top_p=1.0,
)

# Creative: brainstorming, writing
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Write a creative tagline for a coffee shop"}],
    temperature=0.9,
    top_p=0.9,
    top_k=50,
)

# Balanced: general use
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Explain quantum computing briefly"}],
    temperature=0.7,
    top_p=0.9,
)
Where you'll use itTemperature tuning is the primary control for output quality. Use 0 for deterministic tasks (extraction, classification), 0.7 for general chat, and 0.9-1.2 for creative writing.
Under the hoodTemperature divides logits: p_i = exp(z_i / T) / sum(exp(z_j / T)). As T approaches 0, the distribution peaks at the highest logit (greedy). top_p truncates the distribution, removing low-probability tails.

visualize_temperature_effect(logits, [0.1, 0.5, 1.0, 2.0])
# T=0.1: cat=0.999, dog=0.001, bird/fish/horse=~0.000
# T=1.0: cat=0.332, dog=0.222, bird=0.121, fish=0.111, horse=0.106
# T=2.0: cat=0.260, dog=0.235, bird=0.168, fish=0.163, horse=0.158

def sample_with_params(logits, temperature=0.7, top_k=10, top_p=0.9):
    """Combined sampling strategy used in production."""
    logits = logits / temperature
    values, indices = torch.topk(logits, top_k)
    logits[logits < values[:, -1:]] = float("-inf")
    probs = F.softmax(logits, dim=-1)
    sorted_probs, sorted_indices = torch.sort(probs, descending=True)
    cumulative = torch.cumsum(sorted_probs, dim=-1)
    mask = cumulative - sorted_probs > top_p
    sorted_probs[mask] = 0
    sorted_probs /= sorted_probs.sum()
    return sorted_indices[torch.multinomial(sorted_probs, 1)]
Real-World Use CaseA/B testing teams at OpenAI and Anthropic systematically test temperature settings for different task types. Medical diagnosis systems use T=0.0 for deterministic, reproducible answers. Creative writing platforms use T=0.9-1.1 for diverse output. The key insight: production systems often use dynamic temperature — lower for factual follow-ups, higher for open-ended questions within the same conversation.
Internal Behavior Deep-DiveTemperature and top_p work differently: Temperature rescales the entire distribution (preserving relative ordering). top_p physically removes low-probability tokens (changing which tokens are even possible). Combining both gives fine control: temperature adjusts "how focused" while top_p sets "how many options." When both are applied, temperature is applied first, then top_p filters the result.

52max_tokens and Stop Sequences

import asyncio
from openai import AsyncOpenAI, RateLimitError, APITimeoutError

client = AsyncOpenAI()

async def robust_completion(messages, model="gpt-4o", retries=3):
    """Production-grade completion with retry and error handling."""
    for attempt in range(retries):
        try:
            response = await client.chat.completions.create(
                model=model,
                messages=messages,
                temperature=0.0,
                max_tokens=500,
                timeout=30.0,  # 30 second timeout
            )
            return {
                "content": response.choices[0].message.content,
                "tokens_used": response.usage.total_tokens,
                "model": response.model,
                "finish_reason": response.choices[0].finish_reason,
            }
        except RateLimitError:
            wait = 2 ** attempt  # exponential backoff: 1s, 2s, 4s
            print(f"Rate limited. Waiting {wait}s...")
            await asyncio.sleep(wait)
        except APITimeoutError:
            print(f"Timeout on attempt {attempt + 1}")
        except Exception as e:
            print(f"Error: {e}")
            break
    return None

# Usage tracking across requests
async def batch_process(queries: list[str]):
    total_tokens = 0
    results = []
    for q in queries:
        result = await robust_completion([{"role": "user", "content": q}])
        if result:
            total_tokens += result["tokens_used"]
            results.append(result)
    print(f"Processed {len(results)}/{len(queries)} queries, {total_tokens} total tokens")
    return results

asyncio.run(batch_process(["What is Python?", "What is Rust?", "What is Go?"]))

58Transformer Block Anatomy: Attention, FFN, Residual, LayerNorm

What & why. Each transformer block contains two sublayers: multi-head self-attention (computing token relationships) and a feed-forward network (applying non-linear transformation). Each sublayer is wrapped with a residual connection and layer normalization. Understanding this stack explains how LLMs process and store knowledge.

import torch
import torch.nn as nn

class TransformerBlock(nn.Module):
    def __init__(self, d_model: int, n_heads: int, d_ff: int):
        super().__init__()
        self.attention = nn.MultiheadAttention(d_model, n_heads, batch_first=True)
        self.norm1 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU(),
            nn.Linear(d_ff, d_model),
        )
        self.norm2 = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(0.1)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        attn_out, _ = self.attention(x, x, x)
        x = self.norm1(x + self.dropout(attn_out))
        ffn_out = self.ffn(x)
        x = self.norm2(x + self.dropout(ffn_out))
        return x
Where you'll use itUnderstanding transformer blocks explains model capacity, knowledge storage (FFN layers store factual associations), and why fine-tuning certain layers affects different capabilities.
Under the hoodThe residual connection enables gradient flow through deep networks. LayerNorm stabilizes training. The FFN is a two-layer MLP with 4x expansion, and research suggests factual knowledge is primarily stored in FFN parameters.

59RoPE Positional Encoding

What & why. Rotary Position Embedding (RoPE) encodes token positions by rotating query and key vectors in attention, so their dot product naturally decays with distance. Unlike absolute position embeddings, RoPE enables length extrapolation: models trained on 4K context can generalize to 32K+ with proper scaling.

import torch
import math

def rope_rotate(x: torch.Tensor, seq_len: int, base: float = 10000.0):
    """Apply rotary position embedding to query/key tensors."""
    dim = x.shape[-1]
    freqs = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    positions = torch.arange(seq_len).float()
    angles = torch.outer(positions, freqs)

    cos = angles.cos()
    sin = angles.sin()

    x1 = x[..., ::2]
    x2 = x[..., 1::2]
    rotated = torch.stack([
        x1 * cos - x2 * sin,
        x1 * sin + x2 * cos,
    ], dim=-1).flatten(-2)
    return rotated
Where you'll use itRoPE is used in Llama, Mistral, Qwen, and most modern open models. Understanding it explains why some models handle long contexts better.
Under the hoodRoPE applies a rotation matrix to each pair of dimensions in the query and key vectors. The rotation angle is proportional to the token position, creating a distance-dependent attention decay.

60KV Cache Purpose and Mechanics

What & why. During autoregressive generation, each new token attends to all previous tokens. Without caching, this requires recomputing key and value projections for all previous tokens at every step. The KV cache stores previously computed keys and values, reducing generation from O(n^2) to O(n) per step.

import torch

class SimpleAttention(nn.Module):
    def __init__(self, d_model: int):
        super().__init__()
        self.qkv = nn.Linear(d_model, 3 * d_model)

    def forward(self, x, kv_cache=None):
        q, k, v = self.qkv(x).chunk(3, dim=-1)

        if kv_cache is not None:
            k = torch.cat([kv_cache["k"], k], dim=1)
            v = torch.cat([kv_cache["v"], v], dim=1)

        new_cache = {"k": k.detach(), "v": v.detach()}
        attn = torch.softmax(
            q @ k.transpose(-2, -1) / (k.shape[-1] ** 0.5), dim=-1
        )
        return attn @ v, new_cache
Where you'll use itKV caching is fundamental to all LLM serving. It reduces generation latency from quadratic to linear, enables streaming output, and is the basis for prefix caching and paged attention.
Under the hoodThe KV cache stores key and value tensors for each layer and position. For a 70B model with 128K context, the KV cache can consume 40+ GB of VRAM.

69Scaled Dot-Product Attention: QKV Worked Example

What & why. Attention computes: Attention(Q,K,V) = softmax(QK^T / sqrt(d_k)) * V. Queries ask "what am I looking for?", keys say "what do I contain?", and values are the actual content. Scaling by sqrt(d_k) prevents saturation, and softmax converts to weights.

import torch
import torch.nn.functional as F
import math

def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.shape[-1]
    scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    weights = F.softmax(scores, dim=-1)
    return torch.matmul(weights, V), weights

batch, seq_len, d_model = 1, 4, 8
n_heads = 2
d_k = d_model // n_heads

x = torch.randn(batch, seq_len, d_model)
W_q = torch.randn(d_model, d_model)
W_k = torch.randn(d_model, d_model)
W_v = torch.randn(d_model, d_model)

Q = (x @ W_q).view(batch, seq_len, n_heads, d_k).transpose(1, 2)
K = (x @ W_k).view(batch, seq_len, n_heads, d_k).transpose(1, 2)
V = (x @ W_v).view(batch, seq_len, n_heads, d_k).transpose(1, 2)

output, attn_weights = scaled_dot_product_attention(Q, K, V)
print(f"Output shape: {output.shape}")
print(f"Attention weights sum: {attn_weights.sum(dim=-1)}")
Where you'll use itUnderstanding QKV is essential for interpreting attention visualizations, debugging model behavior, and designing attention modifications.
Under the hoodThe sqrt(d_k) scaling prevents dot products from growing too large, which would push softmax into regions with extremely small gradients, destroying gradient flow during training.

70Multi-Head Attention

What & why. Multi-head attention runs multiple attention computations in parallel, each with different learned projections. This allows different heads to capture different relationships: one for syntax, another for coreference, another for structure. Outputs are concatenated and projected back.

import torch
import torch.nn as nn
import math

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model: int, n_heads: int):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.d_k = d_model // n_heads
        self.W_q = nn.Linear(d_model, d_model)
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)

    def forward(self, x):
        B, T, C = x.shape
        Q = self.W_q(x).view(B, T, self.n_heads, self.d_k).transpose(1, 2)
        K = self.W_k(x).view(B, T, self.n_heads, self.d_k).transpose(1, 2)
        V = self.W_v(x).view(B, T, self.n_heads, self.d_k).transpose(1, 2)

        scores = Q @ K.transpose(-2, -1) / math.sqrt(self.d_k)
        weights = torch.softmax(scores, dim=-1)
        out = weights @ V

        out = out.transpose(1, 2).contiguous().view(B, T, C)
        return self.W_o(out)
Where you'll use itMulti-head attention is the core mechanism in all transformer models. Understanding it explains model capacity and why GQA reduces KV cache.
Under the hoodEach head operates on d_k = d_model/n_heads dimensions. Grouped Query Attention (GQA) shares K,V heads across multiple Q heads, reducing KV cache size by 4-8x.

74Speculative Decoding

What & why. Speculative decoding uses a small draft model to generate candidate tokens, verified by the large model in a single forward pass. When the draft predicts correctly, multiple tokens are accepted simultaneously, achieving 2-3x speedup with identical output distribution.

def speculative_decode_step(large_model, small_model, prompt_ids, gamma=5):
    """Simplified speculative decoding step."""
    draft_tokens = []
    draft_input = prompt_ids.clone()
    for _ in range(gamma):
        draft_logits = small_model(draft_input).logits[:, -1, :]
        next_token = draft_logits.argmax(dim=-1)
        draft_tokens.append(next_token)
        draft_input = torch.cat([draft_input, next_token.unsqueeze(1)], dim=1)

    candidate = torch.cat(
        [prompt_ids] + [t.unsqueeze(1) for t in draft_tokens], dim=1
    )
    large_logits = large_model(candidate).logits[:, -gamma - 1 :, :]

    accepted = []
    for draft_token, large_logit in zip(draft_tokens, large_logits):
        large_token = large_logit.argmax(dim=-1)
        if draft_token == large_token:
            accepted.append(draft_token)
        else:
            break
    return accepted
Where you'll use itSpeculative decoding reduces latency for single-request scenarios. It is most effective when the draft model is much smaller (1-2B) than the target model (7-70B).
Under the hoodVerification (scoring multiple tokens in parallel) is cheaper than generation (one token at a time). Accepting 3 out of 5 tokens means 3x speedup with identical output distribution.

79Mixture-of-Experts Routing

What & why. Mixture-of-Experts (MoE) models use sparse activation: only a subset of expert FFN layers process each token. A router network selects top-k experts per token, reducing total FLOPs while maintaining model capacity. This allows training larger models at lower compute cost.

import torch
import torch.nn as nn

class MoELayer(nn.Module):
    def __init__(self, d_model: int, n_experts: int, top_k: int = 2):
        super().__init__()
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(d_model, d_model * 4), nn.GELU(), nn.Linear(d_model * 4, d_model))
            for _ in range(n_experts)
        ])
        self.router = nn.Linear(d_model, n_experts)
        self.top_k = top_k

    def forward(self, x):
        router_logits = self.router(x)
        weights, indices = torch.topk(router_logits.softmax(dim=-1), self.top_k, dim=-1)
        weights = weights / weights.sum(dim=-1, keepdim=True)

        output = torch.zeros_like(x)
        for i, expert in enumerate(self.experts):
            mask = (indices == i).any(dim=-1)
            if mask.any():
                output[mask] += (weights[:, i:i+1] * expert(x[mask])).squeeze(0)
        return output

# Mistral 8x7B: 8 experts, 2 active per token
# Total params: 46.7B, active params: 12.9B
# FLOPs: equivalent to 12.9B dense model
Where you'll use itMoE is used in Mixtral, Qwen-MoE, and DeepSeek-MoE. It enables training models with 100B+ parameters at a fraction of the compute cost of dense models.
Under the hoodThe router learns to specialize experts on different types of inputs (code, math, language). Load balancing losses prevent expert collapse where all tokens route to the same expert.

83TTFT, TBT, and Throughput-Latency Metrics

What & why. Time-to-First-Token (TTFT) measures prompt processing latency. Time-Between-Tokens (TBT) measures generation speed. Throughput measures tokens per second across all requests. These three metrics capture the full performance picture: TTFT for responsiveness, TBT for reading speed, throughput for cost efficiency.

import time
from openai import OpenAI

client = OpenAI()

def benchmark(prompt: str, n_tokens: int = 100):
    """Measure TTFT and TBT for a single request."""
    start = time.time()
    first_token_time = None
    tokens = 0

    stream = client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        max_tokens=n_tokens,
        stream=True,
    )

    for chunk in stream:
        if chunk.choices[0].delta.content:
            if first_token_time is None:
                first_token_time = time.time()
            tokens += 1

    ttft = (first_token_time - start) if first_token_time else float("inf")
    total_time = time.time() - start
    tbt = total_time / max(tokens, 1)
    throughput = tokens / total_time

    return {
        "ttft_ms": ttft * 1000,
        "tbt_ms": tbt * 1000,
        "tokens_per_sec": throughput,
        "total_tokens": tokens,
    }

result = benchmark("Explain quantum computing in detail", n_tokens=200)
print(f"TTFT: {result['ttft_ms']:.0f}ms, "
      f"TBT: {result['tbt_ms']:.0f}ms, "
      f"Throughput: {result['tokens_per_sec']:.0f} tok/s")
Where you'll use itThese metrics are the standard for benchmarking LLM serving. TTFT under 500ms is the target for chat applications. TBT under 30ms per token provides smooth reading experience.
Under the hoodTTFT is dominated by prompt processing (prefill). TBT is dominated by single-token generation (decode). Throughput is maximized by batching, which increases TTFT but improves overall cost efficiency.

import tiktoken

class TokenTracker:
    def __init__(self, db_path: str = "token_usage.db"):
        self.client = OpenAI()
        self.conn = sqlite3.connect(db_path)
        self.conn.execute("""CREATE TABLE IF NOT EXISTS usage (

            input_tokens INTEGER, output_tokens INTEGER,
            cost_usd REAL, latency_ms REAL)""")

        input_tokens = sum(len(enc.encode(m["content"])) for m in messages)

        t0 = time.time()
        response = self.client.chat.completions.create(
            model=model, messages=messages, **kwargs
        )
        latency_ms = (time.time() - t0) * 1000
        output_tokens = response.usage.completion_tokens

        # pricing per 1M tokens
        prices = {"gpt-4o": (2.50, 10.00), "gpt-4o-mini": (0.15, 0.60)}
        inp, outp = prices.get(model, (2.50, 10.00))
        cost = (input_tokens * inp + output_tokens * outp) / 1_000_000

        self.conn.execute(
            "INSERT INTO usage VALUES (NULL, ?, ?, ?, ?, ?, ?)",
            (time.time(), model, input_tokens, output_tokens, cost, latency_ms),
        )
        self.conn.commit()
        return response

from llama_cpp import Llama
import numpy as np

# Load local GGUF model
llm = Llama(model_path="./models/llama-3.1-8b-instruct-q4_k_m.gguf",
            n_ctx=4096, n_gpu_layers=-1, embedding=True)

# Document chunking and embedding
def chunk_and_embed(text: str, chunk_size: int = 512):
    words = text.split()
    chunks = []
    for i in range(0, len(words), chunk_size - 64):
        chunk = " ".join(words[i:i + chunk_size])
        chunks.append(chunk)
    embeddings = [llm.create_embedding(c)["data"][0]["embedding"] for c in chunks]
    return chunks, np.array(embeddings)

def retrieve(query: str, chunks, chunk_embs, k: int = 3):
    q_emb = np.array(llm.create_embedding(query)["data"][0]["embedding"])
    scores = chunk_embs @ q_emb / (np.linalg.norm(chunk_embs, axis=1) * np.linalg.norm(q_emb))
    top_k = np.argsort(scores)[::-1][:k]
    return [(chunks[i], float(scores[i])) for i in top_k]

# Stream answer from retrieved context
def qa(query: str, chunks, chunk_embs):
    context = "\n\n".join(c for c, _ in retrieve(query, chunks, chunk_embs))
    prompt = f"Context:\n{context}\n\nQuestion: {query}\nAnswer:"
    for token in llm(prompt, max_tokens=512, stream=True, temperature=0.3):
        print(token["choices"][0]["text"], end="", flush=True)
