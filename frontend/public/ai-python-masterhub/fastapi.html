1ASGI vs WSGI: Why FastAPI Is Fast

What & why. WSGI (Web Server Gateway Interface) handles one request per thread synchronously, blocking during I/O. ASGI (Asynchronous Server Gateway Interface) extends WSGI with native async/await support, enabling a single worker to handle thousands of concurrent connections via an event loop. FastAPI is built on ASGI through Starlette and powered by uvicorn, giving it performance comparable to Node.js and Go for I/O-bound workloads.

from fastapi import FastAPI

app = FastAPI()

@app.get("/")
async def root():
    return {"message": "Hello"}

# ASGI: event loop handles concurrency without threads
# WSGI: one thread per request (synchronous bottleneck)
Where you'll use itAny API handling concurrent database queries, external HTTP calls, or WebSocket connections benefits from ASGI. ERP2 middleware, fare system gateways, and LLM streaming endpoints all require non-blocking I/O.
Under the hooduvicorn uses uvloop (a libuv-based event loop) which is 2-4x faster than Python's default asyncio loop. The ASGI protocol uses three scope types: http, websocket, and lifespan for lifecycle events.

2Your First App and Uvicorn

What & why. FastAPI creates a typed, self-documenting API in minimal code. Uvicorn is the ASGI server that runs your application. The combination gives you hot-reload development and production-ready serving with zero boilerplate.

pip install fastapi uvicorn
# main.py
from fastapi import FastAPI

app = FastAPI(title="My API", version="0.1.0")

@app.get("/")
async def read_root():
    return {"Hello": "World"}

# Run: uvicorn main:app --reload --host 0.0.0.0 --port 8000
Where you'll use itEvery FastAPI project starts here. The --reload flag is essential during development; in production you run uvicorn with --workers 4 (sync) or behind gunicorn with uvicorn workers.
Under the hoodUvicorn uses the httptools parser (a Cython implementation of HTTP parsing) when available, making request parsing significantly faster than pure-Python alternatives.

3Path Parameters

What & why. Path parameters extract values directly from the URL path and are used to identify specific resources. FastAPI validates them against Python type annotations automatically, returning a 422 error for type mismatches.

from fastapi import FastAPI

app = FastAPI()

@app.get("/users/{user_id}")
async def get_user(user_id: int):
    return {"user_id": user_id}

@app.get("/files/{file_path:path}")
async def read_file(file_path: str):
    return {"file_path": file_path}

# /users/42       -> {"user_id": 42}
# /users/abc      -> 422 Validation Error
Where you'll use itEvery REST API uses path parameters for resource identification: /users/{id}, /orders/{order_id}/items/{item_id}, /api/v2/fares/{route_code}.
Under the hoodFastAPI uses Starlette's URL path converter and pydantic to coerce the string from the URL into the declared Python type. The :path converter allows slashes within the parameter value.

4Query Parameters

What & why. Query parameters appear after the ? in a URL and are used for filtering, pagination, and optional configuration. FastAPI infers them from function signature defaults and validates their types.

from fastapi import FastAPI
from typing import Optional

app = FastAPI()

@app.get("/items/")
async def list_items(
    skip: int = 0,
    limit: int = 10,
    search: Optional[str] = None,
    sort_by: str = "created_at",
):
    return {"skip": skip, "limit": limit, "search": search}
# /items/?skip=20&limit=5&search=widget
Where you'll use itEvery list endpoint uses query parameters for pagination, filtering, and sorting.
Under the hoodParameters with default values become optional query parameters. Parameters without defaults are required.

5Pydantic BaseModel Request Body

What & why. Pydantic models define the shape of JSON request bodies with automatic validation, serialization, and documentation. FastAPI uses these models to validate incoming JSON, generate OpenAPI schemas, and provide editor autocompletion.

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

class UserCreate(BaseModel):
    name: str
    email: EmailStr
    age: int | None = None

app = FastAPI()

@app.post("/users/")
async def create_user(user: UserCreate):
    return {"name": user.name, "email": user.email}

# Request body must be JSON with "name" and "email"
Where you'll use itEvery endpoint that creates or updates resources uses Pydantic models for type-safe input validation.
Under the hoodPydantic v2 uses Rust-based core validation via pydantic-core, making it 5-50x faster than v1. Models use __init__ validation and generate JSON schema at startup.

6response_model Filtering Output

What & why. The response_model parameter controls what fields are returned to the client. Use separate input and output models to prevent exposing sensitive fields like passwords while keeping your endpoint clean.

from fastapi import FastAPI
from pydantic import BaseModel, EmailStr

class UserCreate(BaseModel):
    name: str
    email: EmailStr
    password: str

class UserOut(BaseModel):
    name: str
    email: EmailStr

app = FastAPI()

@app.post("/users/", response_model=UserOut)
async def create_user(user: UserCreate):
    return {"name": user.name, "email": user.email, "hashed_pw": "xxx"}
    # Only name and email returned; password and hashed_pw excluded
Where you'll use itEvery API endpoint should use response_model to enforce output contracts and prevent accidental field leakage.
Under the hoodFastAPI serializes the response through the response_model's Pydantic schema using model_dump() with exclude_unset.

8CRUD Route Methods

What & why. RESTful APIs use HTTP methods to map CRUD operations: GET for reading, POST for creating, PUT/PATCH for updating, and DELETE for removing. FastAPI maps each method to a decorator.

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

class Item(BaseModel):
    name: str
    price: float

app = FastAPI()
items: dict[int, dict] = {}
counter = 0

@app.post("/items/", status_code=201)
async def create_item(item: Item):
    global counter; counter += 1
    items[counter] = item.model_dump()
    return items[counter]

@app.get("/items/{item_id}")
async def read_item(item_id: int):
    if item_id not in items:
        raise HTTPException(status_code=404, detail="Item not found")
    return items[item_id]

@app.put("/items/{item_id}")
async def update_item(item_id: int, item: Item):
    items[item_id] = item.model_dump()
    return items[item_id]

@app.delete("/items/{item_id}", status_code=204)
async def delete_item(item_id: int):
    items.pop(item_id, None)
Where you'll use itEvery resource exposes these five operations. CRUD routes are the backbone of all data-driven APIs.
Under the hoodPUT replaces the entire resource; PATCH updates only provided fields using Pydantic's exclude_unset=True.

9Status Codes

What & why. HTTP status codes communicate the result of an API request. FastAPI uses 200 by default, but you should return semantically correct codes: 201 for creation, 204 for deletion, 404 for not found.

from fastapi import FastAPI, HTTPException
from starlette.status import HTTP_201_CREATED, HTTP_204_NO_CONTENT

app = FastAPI()

@app.post("/resources/", status_code=HTTP_201_CREATED)
async def create_resource():
    return {"id": 1}

@app.get("/resources/{id}")
async def get_resource(id: int):
    if id == 0:
        raise HTTPException(status_code=404, detail="Not found",
            headers={"X-Error-Code": "NOT_FOUND"})
    return {"id": id}

@app.delete("/resources/{id}", status_code=HTTP_204_NO_CONTENT)
async def delete_resource(id: int):
    pass
Where you'll use itCorrect status codes are critical for API clients and load balancers.
Under the hoodHTTPException is caught by FastAPI's exception handling middleware and converted to a JSON response.

11Headers and Cookies

What & why. Headers carry metadata like authentication tokens and request tracing. Cookies maintain state across requests. FastAPI provides Header() and Cookie() dependencies to extract and validate these values.

from fastapi import FastAPI, Header, Cookie
from typing import Annotated

app = FastAPI()

Where you'll use itAuthentication headers and session cookies are extracted using these patterns in every authenticated API.
Under the hoodFastAPI auto-converts header names to lowercase and prepends X- prefix matching. Cookie values are URL-decoded automatically.

12Routing Structure and APIRouter

What & why. FastAPI organizes routes hierarchically with the APIRouter class, supporting path prefixes, tags, and nested routers for scalable, maintainable API organization.

    return {"view": "dashboard"}

# Multiple methods on one path

Where you'll use itEvery non-trivial API uses APIRouter to split routes into modules. The prefix system enables clean versioning.

13Field and Query Validation Constraints

What & why. Pydantic v2 provides rich validation constraints via Annotated types and Field(). You can enforce length limits, numeric ranges, regex patterns, and custom validators directly in your type definitions.

from fastapi import FastAPI, Query
from pydantic import BaseModel, Field
from typing import Annotated

app = FastAPI()

class UserCreate(BaseModel):
    name: Annotated[str, Field(min_length=1, max_length=100)]
    age: Annotated[int, Field(ge=0, le=150)]
    email: Annotated[str, Field(pattern=r"^[\w.-]+@[\w.-]+\.\w+$")]

@app.get("/search/")
async def search(
    q: Annotated[str, Query(min_length=1, max_length=200)],
    page: Annotated[int, Query(ge=1)] = 1,
):
    return {"query": q, "page": page}
Where you'll use itEvery public-facing API uses constraints to prevent abuse.
Under the hoodConstraints are enforced by pydantic-core's Rust validator at C speed. Field() metadata is also used to generate OpenAPI parameter constraints.

14field_validator and model_validator (Pydantic v2)

What & why. When built-in constraints are insufficient, Pydantic v2 provides field_validator for per-field logic and model_validator for cross-field validation, giving you full control while staying within Pydantic's lifecycle.

from pydantic import BaseModel, field_validator, model_validator

class EventCreate(BaseModel):
    title: str
    start_date: str
    end_date: str

    @field_validator("title")
    @classmethod
    def title_not_empty(cls, v: str) -> str:
        if not v.strip():
            raise ValueError("Title must not be blank")
        return v.strip()

    @model_validator(mode="after")
    def end_after_start(self):
        if self.end_date < self.start_date:
            raise ValueError("end_date must be after start_date")
        return self
Where you'll use itCustom validators enforce business rules: date ranges, format normalization, and cross-field dependencies.
Under the hoodThe mode="before" validator runs before Pydantic's type coercion. mode="after" runs after type validation, allowing cross-field checks.

16Depends: Dependency Injection Basics and Chaining

What & why. FastAPI's dependency injection system uses the Depends() callable to declare reusable dependencies. Dependencies can be async functions, classes with __call__, or other dependencies, creating a chain of resolved values.

from fastapi import FastAPI, Depends, Header

app = FastAPI()

async def get_token(authorization: str = Header()) -> str:
    return authorization.replace("Bearer ", "")

async def get_current_user(token: str = Depends(get_token)) -> dict:
    return {"id": 1, "name": "Alice", "token": token}

async def require_admin(user: dict = Depends(get_current_user)) -> dict:
    if user["name"] != "admin":
        from fastapi import HTTPException
        raise HTTPException(status_code=403, detail="Admin required")
    return user

@app.get("/admin/dashboard/")
async def admin_dashboard(admin: dict = Depends(require_admin)):
    return {"welcome": admin["name"]}
# Dependency chain: get_token -> get_current_user -> require_admin
Where you'll use itDI is the backbone of FastAPI. Database sessions, authentication, and permission checks are all injected via Depends.
Under the hoodFastAPI resolves dependencies at request time using a dependency graph. It caches resolved values within a single request.

17HTTPException and Custom Exception Handlers

What & why. HTTPException raises structured HTTP errors. Custom exception handlers let you define application-wide error formats for consistent error responses across your API.

from fastapi import FastAPI, HTTPException, Request
from fastapi.responses import JSONResponse

class AppError(Exception):
    def __init__(self, code: str, message: str, status: int = 400):
        self.code = code; self.message = message; self.status = status

app = FastAPI()

@app.exception_handler(AppError)
async def app_error_handler(request: Request, exc: AppError):
    return JSONResponse(status_code=exc.status,
        content={"error": {"code": exc.code, "message": exc.message}})

@app.get("/orders/{order_id}")
async def get_order(order_id: int):
    if order_id == 0:
        raise HTTPException(status_code=404, detail="Not found")
    if order_id == -1:
        raise AppError(code="INVALID_ID", message="Negative IDs not allowed")
    return {"id": order_id}
Where you'll use itCustom exception handlers ensure all errors follow a consistent schema.
Under the hoodException handlers are checked in reverse registration order. You can override built-in handlers for validation errors.

18Middleware

What & why. Middleware runs before and after every request, enabling cross-cutting concerns like logging, timing, and request ID injection.

import time, uuid
from fastapi import FastAPI, Request

app = FastAPI()

@app.middleware("http")
async def add_process_time(request: Request, call_next):
    request_id = str(uuid.uuid4())[:8]
    start = time.perf_counter()
    response = await call_next(request)
    elapsed = time.perf_counter() - start
    response.headers["X-Request-ID"] = request_id
    response.headers["X-Process-Time"] = f"{elapsed:.4f}"
    return response

@app.get("/fast")
async def fast_endpoint():
    return {"message": "FastAPI is fast"}
Where you'll use itRequest logging, distributed tracing, and response timing are implemented as middleware in every production API.
Under the hoodMiddleware wraps the ASGI application stack. Each middleware receives scope, receive, and send callables. call_next invokes the next middleware or handler.

19BackgroundTasks

What & why. BackgroundTasks lets you run functions after sending the response. This is ideal for sending emails, writing logs, or any work that doesn't need to block the response.

import logging
from fastapi import FastAPI, BackgroundTasks

logger = logging.getLogger(__name__)
app = FastAPI()

def send_welcome_email(email: str, name: str):
    logger.info(f"Sending welcome email to {email}")

@app.post("/register/")
async def register(email: str, name: str, background_tasks: BackgroundTasks):
    background_tasks.add_task(send_welcome_email, email, name)
    return {"message": "User registered"}
# Response sent immediately; email runs after
Where you'll use itBackground tasks handle email notifications, audit logging, and analytics events.
Under the hoodBackgroundTasks execute after the response is sent but within the same ASGI scope. For long-running tasks, use Celery instead.

22SQLAlchemy 2.0 Async Session and Alembic

What & why. SQLAlchemy 2.0 supports async via AsyncSession. FastAPI's DI system provides database sessions as injected dependencies. Alembic manages schema migrations for safe deployments.

from fastapi import FastAPI, Depends
from sqlalchemy.ext.asyncio import (
    create_async_engine, async_sessionmaker, AsyncSession
)
from sqlalchemy.orm import DeclarativeBase, Mapped, mapped_column

engine = create_async_engine("sqlite+aiosqlite:///./app.db")
AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)

class Base(DeclarativeBase): pass
class User(Base):
    __tablename__ = "users"
    id: Mapped[int] = mapped_column(primary_key=True)
    name: Mapped[str]

async def get_db() -> AsyncSession:
    async with AsyncSessionLocal() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise

app = FastAPI()

@app.get("/users/")
async def list_users(db: AsyncSession = Depends(get_db)):
    from sqlalchemy import select
    result = await db.execute(select(User))
    return [{"id": u.id, "name": u.name} for u in result.scalars().all()]

# Alembic: alembic init alembic
# Auto-generate: alembic revision --autogenerate -m "add users"
# Apply: alembic upgrade head
Where you'll use itEvery database-backed FastAPI app uses this pattern. The yield dependency ensures sessions are committed or rolled back per request.
Under the hoodThe yield dependency splits into setup and teardown. SQLAlchemy's async engine uses aiosqlite for SQLite or asyncpg for PostgreSQL.

23OAuth2 Password Flow and JWT

What & why. OAuth2 with password flow provides token-based authentication. JWT encodes user identity and claims in a signed token. FastAPI includes built-in OAuth2PasswordBearer and integrates with python-jose.

from datetime import datetime, timedelta
from fastapi import FastAPI, Depends, HTTPException
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from jose import JWTError, jwt
from passlib.context import CryptContext

SECRET_KEY = "change-in-production"; ALGORITHM = "HS256"
pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")
app = FastAPI()

def create_access_token(data: dict) -> str:
    to_encode = data.copy()
    to_encode.update({"exp": datetime.utcnow() + timedelta(minutes=30)})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)

async def get_current_user(token: str = Depends(oauth2_scheme)):
    try:
        return jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
    except JWTError:
        raise HTTPException(status_code=401, detail="Invalid token")

@app.post("/token")
async def login(form: OAuth2PasswordRequestForm = Depends()):
    return {"access_token": create_access_token({"sub": form.username})}

@app.get("/me/")
async def read_me(user: dict = Depends(get_current_user)):
    return {"username": user["sub"]}
Where you'll use itJWT authentication is the standard for API security in every user-facing API.
Under the hoodOAuth2PasswordBearer adds the Bearer token to OpenAPI docs automatically. python-jose handles JWT encoding/decoding with cryptographic verification.

24Scoped Role Dependencies

What & why. Role-based access control restricts endpoints to users with specific permissions. FastAPI's DI system makes it elegant to compose role-checking dependencies that stack on top of authentication.

from enum import Enum
from fastapi import FastAPI, Depends, HTTPException, status

class Role(str, Enum):
    USER = "user"
    ADMIN = "admin"
    SUPERADMIN = "superadmin"

def require_role(*allowed_roles: Role):
    async def role_checker(user: dict = Depends(get_current_user)):
        user_role = Role(user.get("role", "user"))
        if user_role not in allowed_roles:
            raise HTTPException(status_code=403, detail="Forbidden")
        return user
    return role_checker

app = FastAPI()

@app.get("/dashboard/")
async def dashboard(user: dict = Depends(require_role(Role.USER))):
    return {"user": user}

@app.get("/admin/users/")
async def admin_users(user: dict = Depends(require_role(Role.ADMIN))):
    return {"admin": True}
Where you'll use itRBAC is mandatory for any API with multiple user types.
Under the hoodThe require_role factory creates a closure over allowed roles. The DI chain ensures authentication runs before authorization.

25Yield Dependencies and Teardown

What & why. Yield dependencies split setup and teardown. Code before yield initializes resources; code after yield cleans up, ensuring resources are always released even on errors.

import logging
from fastapi import FastAPI, Depends

logger = logging.getLogger(__name__)
app = FastAPI()

async def get_db_connection():
    conn = await create_connection()
    logger.info("Connection opened")
    try:
        yield conn
    finally:
        await conn.close()
        logger.info("Connection closed")

async def get_audit_log(conn=Depends(get_db_connection)):
    audit = AuditLog(conn)
    try:
        yield audit
    except Exception as exc:
        await audit.log_error(exc)
        raise

@app.get("/data/")
async def get_data(audit=Depends(get_audit_log)):
    return await audit.query("SELECT * FROM data")
Where you'll use itEvery database dependency and external service client uses yield dependencies to guarantee cleanup.
Under the hoodFastAPI converts the generator into a context manager. Dependencies are resolved in dependency order and torn down in reverse.

26WebSocket Endpoints

What & why. WebSockets provide persistent bidirectional communication. FastAPI makes WebSocket endpoints as simple as HTTP routes with native async support.

from fastapi import FastAPI, WebSocket, WebSocketDisconnect
import json

app = FastAPI()

class ConnectionManager:
    def __init__(self):
        self.active: list[WebSocket] = []
    async def connect(self, ws: WebSocket):
        await ws.accept(); self.active.append(ws)
    def disconnect(self, ws: WebSocket):
        self.active.remove(ws)
    async def broadcast(self, message: dict):
        for conn in self.active:
            await conn.send_json(message)

manager = ConnectionManager()

@app.websocket("/ws/{client_id}")
async def websocket_endpoint(ws: WebSocket, client_id: str):
    await manager.connect(ws)
    try:
        while True:
            data = await ws.receive_json()
            await manager.broadcast({"sender": client_id, "message": data["message"]})
    except WebSocketDisconnect:
        manager.disconnect(ws)
Where you'll use itReal-time chat, live dashboards, and notification systems all use WebSockets.

29async def vs def: Threadpool Behavior

What & why. FastAPI runs async def handlers on the event loop and sync def handlers in a threadpool. Choosing incorrectly can block the entire server.

from fastapi import FastAPI
import asyncio, httpx

app = FastAPI()

# GOOD: async for I/O-bound operations
@app.get("/async/")
async def async_handler():
    async with httpx.AsyncClient() as client:
        resp = await client.get("https://api.example.com/data")
    return resp.json()

# BAD: async with blocking I/O
@app.get("/bad/")
async def bad_handler():
    import time
    time.sleep(1)  # BLOCKS THE ENTIRE EVENT LOOP
    return {"result": "done"}

# ACCEPTABLE: sync for blocking library code (runs in threadpool)
@app.get("/sync/")
def sync_handler():
    import time
    time.sleep(1)  # Blocks this thread only, event loop continues
    return {"result": "done"}
Where you'll use itUse async for database queries (asyncpg), HTTP calls (httpx), and Redis. Use sync handlers for libraries without async support.
Under the hoodFastAPI uses Starlette's threadpool (via anyio) for sync handlers. Default threadpool size is 40. Blocking the event loop freezes all concurrent requests.

37Connection Pool Tuning

What & why. Database connection pools manage reusable connections. Correct pool sizing balances concurrency with database resource limits.

from sqlalchemy.ext.asyncio import create_async_engine

engine = create_async_engine(
    "postgresql+asyncpg://user:pass@localhost/db",
    pool_size=20,          # fixed pool of persistent connections
    max_overflow=10,       # temporary overflow connections
    pool_timeout=30,       # seconds to wait for a connection
    pool_recycle=1800,     # recycle connections after 30 minutes

)
