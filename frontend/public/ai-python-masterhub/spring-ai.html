1What Spring AI Adds to Spring Boot

What & why. Spring AI is a Spring project that provides a unified abstraction layer for interacting with LLMs from within Spring Boot applications. It eliminates the need to wire HTTP clients, manage API keys manually, or write provider-specific boilerplate. By adding a single starter dependency, you gain access to a consistent ChatClient API that works across OpenAI, Azure OpenAI, Ollama, Bedrock, Vertex AI, and other providers — following the same Spring convention of pluggable implementations behind stable interfaces.

<!-- pom.xml -->
<dependency>
  <groupId>org.springframework.ai</groupId>
  <artifactId>spring-ai-openai-spring-boot-starter</artifactId>
</dependency>

<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
</dependency>
Where you'll use itAny Spring Boot microservice that needs to call an LLM — chatbots, summarizers, classification pipelines, content generators — starts with this starter.
Under the hoodThe starter auto-configures an OpenAiChatModel bean backed by an HTTP client, reading API key and base URL from Spring properties. You inject the model or ChatClient directly into your beans.

What & why. Spring Boot's auto-configuration reads properties from application.yml to configure the LLM client. The API key, model name, temperature, and endpoint URL are all externalized. Spring profiles let you switch between providers (dev uses Ollama, prod uses OpenAI) without code changes — just profile-specific property files.

          temperature: 0.5
Where you'll use itEvery Spring AI application reads provider config from properties. Profile-based switching lets developers test locally with Ollama and deploy to OpenAI in production.
Under the hoodSpring Boot auto-configuration detects which starter is on the classpath and creates the corresponding ChatModel bean. Multiple starters can coexist with @Primary annotation selecting the default.

3ChatClient Basic Call

What & why. ChatClient is the primary abstraction for calling LLMs in Spring AI. It wraps the underlying ChatModel and provides a fluent, builder-style API for constructing prompts, calling the model, and extracting responses. You create it via ChatClient.create(chatModel) or inject it as a Spring bean. Every call returns a ChatResponse containing the generated text, token usage, and metadata.

import org.springframework.ai.chat.client.ChatClient;

@Service
public class ChatService {
    private final ChatClient chatClient;

    public ChatService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public String ask(String question) {
        return chatClient.prompt()
            .user(question)
            .call()
            .content();
    }
}
Where you'll use itEvery LLM interaction in a Spring AI app goes through ChatClient. It is the equivalent of JdbcTemplate for databases — a clean, idiomatic Spring API for a complex external service.
Under the hoodChatClient.Builder is auto-configured as a bean with the active ChatModel injected. Calling .build() creates an immutable client. The .call() method blocks and returns the full response; .stream() returns a reactive Flux.

4Prompt Templates with Placeholders

What & why. Prompt templates allow parameterized prompts with {placeholder} syntax, separating prompt structure from runtime data. Spring AI supports system and user message templates via the PromptTemplate class. Placeholders are replaced using MapSqlParameterSource-style variable binding. This is essential for building reusable prompts that adapt to different inputs.

import org.springframework.ai.chat.prompt.PromptTemplate;
import org.springframework.ai.chat.messages.SystemMessage;
import org.springframework.ai.chat.messages.UserMessage;

// Template with placeholders
String template = "You are a {role} assistant. "
    + "Answer the following question about {topic}: {question}";

PromptTemplate promptTemplate = new PromptTemplate(template);
var message = promptTemplate.createMessage(Map.of(
    "role", "senior Java architect",
    "topic", "Spring Boot",
    "question", "How do I configure connection pooling?"
));

// System vs user message separation
var systemMsg = new SystemMessage("You are a concise technical writer.");
var userMsg = new UserMessage(message.getText());

ChatResponse response = chatClient.prompt()
    .system(systemMsg)
    .user(userMsg)
    .call()
    .chatResponse();
Where you'll use itTemplated prompts power every chatbot, classifier, and content generator. System messages set behavior rules; user messages carry the actual input — this separation is critical for reliable outputs.
Under the hoodSpring AI uses SpEL (Spring Expression Language) or simple {name} placeholder resolution. The PromptTemplate compiles the template once and creates new message instances per call.

5System vs User Messages

What & why. LLMs distinguish between system messages (instructions about behavior, tone, constraints) and user messages (the actual input). System messages define the persona and rules; user messages carry the query. Getting this separation right prevents prompt injection and ensures consistent outputs. Spring AI models this as SystemMessage and UserMessage classes.

import org.springframework.ai.chat.messages.SystemMessage;
import org.springframework.ai.chat.messages.UserMessage;

SystemMessage system = new SystemMessage(
    "You are a financial analyst. "
    + "Only answer questions about publicly traded companies. "
    + "Never provide buy/sell recommendations."
);

UserMessage user = new UserMessage(
    "What was Apple's revenue last quarter?"
);

ChatResponse response = chatClient.prompt()
    .system(system)
    .user(user)
    .call()
    .chatResponse();
Where you'll use itSystem messages enforce guardrails — role definitions, output format requirements, and safety rules. Without them, the model has no instructions and produces generic outputs.
Under the hoodThe system message is prepended to the prompt in the API request. Most providers charge tokens for both. Keep system messages concise but complete — they are processed first by the model and have strong influence.

6Streaming Responses with Flux

What & why. Streaming sends LLM output token-by-token as it is generated, reducing time-to-first-token from seconds to milliseconds. Spring AI exposes streaming via reactive Flux<String> from chatClient.prompt().stream(). This is essential for responsive chat UIs where users expect to see text appear in real-time rather than waiting for the complete response.

import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Flux;

@RestController
public class ChatStreamController {
    private final ChatClient chatClient;

    public ChatStreamController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    @GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<String> stream(@RequestParam String message) {
        return chatClient.prompt()
            .user(message)
            .stream()
            .content();
    }
}
Where you'll use itChat UIs, real-time translation, and interactive agents all require streaming. Users perceive streaming as 3-5x faster even when total generation time is identical.
Under the hoodThe underlying HTTP client uses Server-Sent Events (SSE) or chunked transfer encoding. Spring AI buffers tokens into a Flux<ChatResponse> and extracts text via .content(). WebFlux or servlet async support handles the reactive pipeline.

7Simple REST Controller Exposing Chat

What & why. A REST controller wraps the ChatClient in an HTTP endpoint that accepts user messages and returns LLM responses. This is the standard pattern for exposing AI capabilities to frontend apps, mobile clients, or other microservices. Use @RestController with @PostMapping for structured input and proper error handling.

@RestController
@RequestMapping("/api/chat")
public class ChatController {
    private final ChatClient chatClient;

    public ChatController(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public record ChatRequest(String message) {}
    public record ChatResponse(String reply) {}

    @PostMapping
    public ChatResponse chat(@RequestBody ChatRequest request) {
        String reply = chatClient.prompt()
            .user(request.message())
            .call()
            .content();
        return new ChatResponse(reply);
    }
}
Where you'll use itThe REST controller is the integration boundary between your AI backend and any consumer. It decouples the LLM interaction from the transport layer.
Under the hoodSpring Boot auto-configures Jackson serialization for records. The controller method blocks on the LLM call; for high-concurrency, use the streaming endpoint with Flux and reactive streams instead.

10Model Options: Temperature and Beyond

What & why. Model options control generation behavior — temperature affects creativity vs. consistency, max tokens limits response length, top-p and top-k control sampling diversity. Spring AI lets you set defaults in configuration and override per-request via the ChatClient. Understanding these parameters is essential for tuning output quality for different use cases.

# Global defaults in application.yml
spring:
  ai:
    openai:
      chat:
        options:
          model: gpt-4o
          temperature: 0.7
          max-tokens: 4096
          top-p: 0.95

// Per-request override in Java
ChatResponse response = chatClient.prompt()
    .user("Write a creative poem about the ocean")
    .options(OpenAiChatOptions.builder()
        .temperature(1.2)
        .maxTokens(1024)
        .build())
    .call()
    .chatResponse();

// Low temperature for factual responses
ChatResponse factual = chatClient.prompt()
    .user("What is the capital of France?")
    .options(OpenAiChatOptions.builder()
        .temperature(0.0)
        .build())
    .call()
    .chatResponse();
Where you'll use itTemperature 0.0 for extraction and classification (deterministic), 0.7 for conversational agents (balanced), 1.0+ for creative writing (diverse). Per-request overrides let one service handle multiple use cases.
Under the hoodTemperature controls the randomness of token sampling via the softmax probability distribution. Lower values sharpen the distribution toward the most likely token; higher values flatten it.

11Structured Output: Hello World with BeanOutputConverter

What & why. Structured output forces the LLM to return JSON conforming to a Java class schema. Spring AI's BeanOutputConverter sends the schema to the model and parses the response into a typed POJO. This eliminates manual JSON parsing and enables compile-time safety for LLM outputs.

import org.springframework.ai.converter.BeanOutputConverter;

public record TravelPlan(
    String destination,
    int days,
    List<String> highlights,
    double estimatedCost
) {}

@Service
public class TravelService {
    private final ChatClient chatClient;
    private final BeanOutputConverter<TravelPlan> converter =
        new BeanOutputConverter<>(TravelPlan.class);

    public TravelPlan planTrip(String request) {
        String format = converter.getFormat();
        String prompt = "Create a travel plan as JSON matching this schema: "
            + format + "\n\nRequest: " + request;

        return chatClient.prompt()
            .user(prompt)
            .call()
            .convert(converter);
    }
}
Where you'll use itStructured output is critical for pipelines that feed LLM responses into downstream systems — database storage, API responses, and multi-step workflows all need typed, validated data.
Under the hoodBeanOutputConverter generates a JSON schema from the Java class, injects it into the prompt, and uses Jackson to deserialize the model's JSON response. It includes retry logic for malformed outputs.

13ChatClient Fluent API Chain Deep Use

What & why. The ChatClient fluent API supports chaining system prompts, user messages, advisors, options, and output converters in a single declarative expression. Each method in the chain adds a configuration layer, and .call() or .stream() triggers execution. Deep chaining reduces boilerplate and makes the full prompt configuration readable at a glance.

String result = chatClient.prompt()
    .system(s -> s.text("You are a {role}")
                .param("role", "senior backend engineer"))
    .user(u -> u.text("Review this code for security issues: {code}")
                .param("code", sourceCode))
    .advisors(new MessageChatMemoryAdvisor(chatMemory))
    .options(OpenAiChatOptions.builder()
        .model("gpt-4o")
        .temperature(0.1)
        .maxTokens(4096)
        .build())
    .call()
    .content();

// Streaming variant with Flux
Flux<String> stream = chatClient.prompt()
    .system("You are a helpful coding assistant")
    .user(userQuestion)
    .stream()
    .content();
Where you'll use itFluent chains make prompt configuration self-documenting. Each adapter in the chain (system, user, advisors, options) is visible without jumping between methods.
Under the hoodThe builder accumulates configuration state until .call() is invoked. Advisors execute as an ordered chain of interceptors before the request reaches the LLM, similar to Spring's HandlerInterceptor pattern.

14Advisors: RequestResponseAdvisor Concept

What & why. Advisors are Spring AI's interceptor pattern for modifying, logging, or augmenting LLM requests and responses. They implement RequestResponseAdvisor and execute in an ordered chain around every LLM call. Use advisors for cross-cutting concerns: adding context, enforcing guardrails, logging prompts, managing memory, or retrieving documents for RAG.

import org.springframework.ai.chat.client.advisor.RequestResponseAdvisor;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.ai.chat.prompt.Prompt;

public class LoggingAdvisor implements RequestResponseAdvisor {
    private static final Logger log =
        LoggerFactory.getLogger(LoggingAdvisor.class);

    @Override
    public Prompt adviseRequest(Prompt prompt, Map<String, Object> context) {
        log.info("LLM request: {} messages, model={}",
            prompt.getMessages().length,
            prompt.getChatOptions());
        return prompt;
    }

    @Override
    public ChatResponse adviseResponse(ChatResponse response,
                                       Map<String, Object> context) {
        log.info("LLM response: tokens={}",
            response.getMetadata().getUsage());
        return response;
    }

    @Override
    public int getOrder() {
        return 0;  // lower = executes first
    }
}

// Register advisors on ChatClient
chatClient = ChatClient.builder(chatModel)
    .defaultAdvisors(new LoggingAdvisor())
    .build();
Where you'll use itAdvisors replace scattered if/else logic with composable, ordered interceptors. Add logging, guardrails, or RAG retrieval without modifying business logic.
Under the hoodAdvisors execute in getOrder() sequence — lower values run first on request, last on response. The chain is inspired by Spring Security's filter chain and Servlet filter ordering.

15ChatMemory Advisors: Message Window Management

What & why. MessageChatMemoryAdvisor stores conversation history and injects it into each request, enabling multi-turn conversations. It uses a sliding window strategy — keeping the last N messages (configurable) to manage token limits. Memory is stored per conversation ID, so different chat sessions are isolated.

import org.springframework.ai.chat.client.advisor.MessageChatMemoryAdvisor;
import org.springframework.ai.chat.memory.InMemoryChatMemory;
import org.springframework.ai.chat.memory.ChatMemory;

@Service
public class ConversationService {
    private final ChatClient chatClient;
    private final ChatMemory chatMemory = new InMemoryChatMemory();

    public ConversationService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
    }

    public String chat(String conversationId, String message) {
        return chatClient.prompt()
            .system("You are a helpful assistant with memory")
            .user(message)
            .advisors(a -> a.param(
                ChatMemory.CONVERSATION_ID, conversationId))
            .advisors(new MessageChatMemoryAdvisor(
                chatMemory, conversationId, 20)) // window=20 messages
            .call()
            .content();
    }
}
Where you'll use itEvery conversational AI needs memory. The message window prevents context from growing unbounded while maintaining recent conversation coherence. Map-backed storage is ideal for development; JDBC or Redis adapters handle production.
Under the hoodThe advisor retrieves past messages from ChatMemory for the given CONVERSATION_ID, prepends them to the current prompt, and stores the new exchange after the call completes.

16PromptTemplate with List Items

What & why. Complex prompts often include dynamic lists — bullet points of requirements, code snippets, or document excerpts. Spring AI's PromptTemplate supports variable binding for lists and structured objects. You construct the list in Java, bind it as a template variable, and the template renders it into the prompt text.

import org.springframework.ai.chat.prompt.PromptTemplate;

List<String> requirements = List.of(
    "Must support OAuth 2.0 authentication",
    "Response time under 200ms at P99",
    "Horizontal scaling to 10k RPM",
    "Audit logging for all mutations"
);

String template = """
    You are a solutions architect. Design a system with these requirements:
    {requirements}

    Provide architecture, technology choices, and trade-offs.
    """;

PromptTemplate pt = new PromptTemplate(template);
String rendered = pt.render(Map.of(
    "requirements", requirements.stream()
        .map(r -> "- " + r)
        .collect(Collectors.joining("\n"))
));

ChatResponse response = chatClient.prompt()
    .user(rendered)
    .call()
    .chatResponse();
Where you'll use itDynamic list injection is essential for prompts that process variable-length inputs — requirement lists, code review checklists, document excerpts for summarization, or multi-item classification tasks.
Under the hoodThe render() method performs simple string interpolation of bound variables. No SpEL evaluation occurs for plain variable substitution — variables are replaced via String.replace() style matching.

17BeanOutputConverter: Structured Output to POJO

What & why. BeanOutputConverter converts unstructured LLM text into typed Java objects by providing a JSON schema to the model and deserializing the response. It handles retries for malformed output and enforces schema compliance. This is the foundation for building reliable LLM-powered data extraction pipelines.

import org.springframework.ai.converter.BeanOutputConverter;

public record CodeReview(
    String summary,
    List<Issue> issues,
    String overallRisk
) {
    public record Issue(
        String severity,
        String description,
        String suggestion
    ) {}
}

@Service
public class CodeReviewService {
    private final ChatClient chatClient;
    private final BeanOutputConverter<CodeReview> converter =
        new BeanOutputConverter<>(CodeReview.class);

    public CodeReview review(String code) {
        return chatClient.prompt()
            .system("You are a code reviewer. "
                + "Return your review as JSON matching this schema: "
                + converter.getFormat())
            .user("Review this code:\n" + code)
            .call()
            .convert(converter);
    }
}
Where you'll use itStructured output enables LLM responses to feed directly into databases, APIs, and downstream services without manual parsing. This is critical for reliable automation.
Under the hoodThe converter generates a JSON schema from the record, embeds it in the prompt, and uses Jackson to deserialize the response. It retries up to 3 times if the model returns invalid JSON.

18@Tool Annotated Functions and Registration

What &why. Spring AI's @Tool annotation marks Java methods as callable functions that the LLM can invoke during conversation. The model receives tool descriptions, decides which to call based on the user's request, and Spring AI executes the Java method and returns the result. This bridges LLM reasoning with real-world actions.

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;

@Service
public class EmployeeTools {
    private final LeaveRepository leaveRepo;

    @Tool(description = "Check remaining leave balance for an employee")
    public LeaveBalance checkLeaveBalance(
            @ToolParam(description = "Employee ID") String empId) {
        return leaveRepo.findByEmployeeId(empId);
    }

    @Tool(description = "Submit a leave request with start and end dates")
    public LeaveRequest submitLeave(
            @ToolParam(description = "Employee ID") String empId,
            @ToolParam(description = "Start date, format YYYY-MM-DD") String start,
            @ToolParam(description = "End date, format YYYY-MM-DD") String end) {
        return leaveRepo.createRequest(empId, start, end);
    }
}

// Register tools on ChatClient
ChatClient client = ChatClient.builder(chatModel)
    .defaultTools(new EmployeeTools(leaveRepo))
    .build();
Where you'll use itTool calling transforms LLMs from text generators into action-capable agents. Use for database queries, API calls, form submissions, and any real-world operation triggered by natural language.
Under the hoodSpring AI serializes tool definitions (name, description, parameters) into the API's function-calling format. When the model returns a tool call, the framework deserializes arguments, invokes the method, and feeds the result back to the model.

19Function Calling Callbacks

What & why. Function calling lets the LLM request execution of named functions mid-conversation. Spring AI maps function names to Java beans via FunctionCallback registrations. The model outputs a function call with arguments, the framework executes the matching Java method, and the result is sent back to the model for final response generation. This enables multi-step reasoning with real data access.

import org.springframework.ai.chat.model.ChatModel;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.context.annotation.Bean;

@Configuration
public class ToolConfig {
    @Bean
    public Function<WeatherRequest, WeatherResponse> weatherFunction() {
        return request -> {
            // Call real weather API
            double temp = weatherService.getTemp(request.city());
            return new WeatherResponse(request.city(), temp, "sunny");
        };
    }
}

// Register via ChatClient builder
chatClient = ChatClient.builder(chatModel)
    .defaultFunctions("weatherFunction")
    .build();

// The model may call: weatherFunction({"city": "Singapore"})
String response = chatClient.prompt()
    .user("What is the weather in Singapore?")
    .call()
    .content();
Where you'll use itFunction callbacks are the backbone of AI agents. The model reasons about when to call which function, and Spring AI handles the execution plumbing — enabling conversational interfaces to real systems.
Under the hoodFunctions are registered by name and description. The model receives available functions as tool definitions in the API request. When it decides to call a function, the response includes a tool_calls array that Spring AI processes automatically.

20EmbeddingModel Interface and Embed Calls

What & why. EmbeddingModel converts text into numerical vectors (embeddings) that capture semantic meaning. Spring AI's EmbeddingModel interface provides a embed() method that returns List<Float> vectors. These vectors power similarity search, clustering, classification, and RAG retrieval. The same interface works across providers (OpenAI, Ollama, Azure).

import org.springframework.ai.embedding.EmbeddingModel;
import org.springframework.ai.embedding.EmbeddingResponse;

@Service
public class EmbeddingService {
    private final EmbeddingModel embeddingModel;

    public EmbeddingService(EmbeddingModel embeddingModel) {
        this.embeddingModel = embeddingModel;
    }

    public float[] embed(String text) {
        EmbeddingResponse response = embeddingModel.call(
            new EmbeddingRequest(List.of(text),
                OpenAiEmbeddingOptions.builder()
                    .model("text-embedding-3-small")
                    .build()));
        return response.getResult().getOutput().getFloatVector();
    }

    public List<float[]> embedBatch(List<String> texts) {
        EmbeddingResponse response = embeddingModel.call(
            new EmbeddingRequest(texts, null));
        return response.getResults().stream()
            .map(r -> r.getOutput().getFloatVector())
            .collect(Collectors.toList());
    }
}
Where you'll use itEmbeddings are the foundation of semantic search and RAG. Every document and query must be embedded before similarity comparison. Batch embedding reduces API calls and latency.
Under the hoodThe EmbeddingModel auto-configuration reads provider properties and creates the appropriate client. OpenAI text-embedding-3-small returns 1536-dimensional vectors; Ollama models may use different dimensions.

21SimpleVectorStore: In-Memory RAG Mini

What & why. SimpleVectorStore is Spring AI's in-memory vector store for development and small datasets. It stores embeddings in a Map and performs cosine similarity search at query time. Combined with an EmbeddingModel, it provides a complete RAG (Retrieval-Augmented Generation) pipeline without external databases.

import org.springframework.ai.vectorstore.SimpleVectorStore;
import org.springframework.ai.vectorstore.SearchRequest;

@Service
public class MiniRagService {
    private final SimpleVectorStore vectorStore;
    private final EmbeddingModel embeddingModel;

    public MiniRagService(EmbeddingModel embeddingModel) {
        this.embeddingModel = embeddingModel;
        this.vectorStore = new SimpleVectorStore(embeddingModel);
    }

    public void indexDocuments(List<Document> docs) {
        vectorStore.add(docs);
    }

    public String query(String question, int topK) {
        SearchRequest request = SearchRequest.query(question)
            .withTopK(topK)
            .withSimilarityThreshold(0.7);

        List<Document> results = vectorStore.similaritySearch(request);
        String context = results.stream()
            .map(Document::getContent)
            .collect(Collectors.joining("\n---\n"));

        return chatClient.prompt()
            .system("Answer based on the provided context only")
            .user("Context:\n" + context + "\n\nQuestion: " + question)
            .call()
            .content();
    }
}
Where you'll use itSimpleVectorStore is ideal for prototyping RAG without external dependencies. For production, swap to PgVector, Redis, or Milvus — the VectorStore interface is identical.
Under the hoodCosine similarity is computed by iterating all stored vectors and computing dot product / magnitudes. Performance degrades above ~100k documents — switch to a proper vector database for larger datasets.

26Multi-Advisor Ordering and Composition

What & why. Multiple advisors execute in getOrder() sequence. The order matters: RAG retrieval should run before guardrails (check retrieved content), memory should run after RAG (avoid injecting memory into retrieved context). Understanding advisor composition prevents subtle bugs like double-injection of context or guardrails bypassing retrieved content.

// Advisor execution order: lower order = runs first
// RAG (order=100) -> Guardrails (order=200) -> Memory (order=300)

public class GuardrailAdvisor implements RequestResponseAdvisor {
    @Override
    public Prompt adviseRequest(Prompt prompt, Map<String, Object> ctx) {
        // Runs AFTER RAG has added context — validates final prompt
        String content = prompt.getContents();
        if (containsSensitiveData(content)) {
            throw new GuardrailViolationException(
                "Prompt contains sensitive data");
        }
        return prompt;
    }

    @Override
    public int getOrder() { return 200; }
}

// Composition on ChatClient
ChatClient client = ChatClient.builder(chatModel)
    .defaultAdvisors(
        new QuestionAnswerAdvisor(vectorStore),    // order 100
        new GuardrailAdvisor(),                     // order 200
        new MessageChatMemoryAdvisor(chatMemory)    // order 300
    )
    .build();
Where you'll use itAdvisor ordering determines the security and quality properties of your AI pipeline. Incorrect ordering can allow prompt injection through retrieved documents or double-process user messages.
Under the hoodThe advisor chain follows the decorator pattern — each advisor wraps the next, modifying the request on the way in and the response on the way out. The order determines the nesting depth.

31Evaluation Stub: Evaluator and RelevancyEvaluator

What & why. Spring AI includes an evaluation framework for measuring LLM response quality. RelevancyEvaluator checks whether a response is relevant to the input question. Custom Evaluator implementations measure domain-specific metrics. Evaluation is essential for regression testing prompts and catching quality degradation after changes.

import org.springframework.ai.evaluation.RelevancyEvaluator;

@Service
public class EvaluationService {
    private final ChatClient chatClient;
    private final RelevancyEvaluator evaluator;

    public EvaluationService(ChatClient.Builder builder) {
        this.chatClient = builder.build();
        this.evaluator = new RelevancyEvaluator(chatClient);
    }

    public EvaluationResult evaluate(String question, String answer) {
        ChatResponse chatResponse = new ChatResponse(
            List.of(new Generation(answer)));

        return evaluator.evaluate(
            new EvaluationRequest(question, chatResponse));
    }

    public void runEvaluationSuite(String[] questions) {
        int passed = 0;
        for (String q : questions) {
            String answer = chatClient.prompt()
                .user(q).call().content();
            EvaluationResult result = evaluate(q, answer);
            if (result.isPass()) passed++;
            System.out.printf("Q: %s -> %s%n", q,
                result.isPass() ? "PASS" : "FAIL");
        }
        System.out.printf("Score: %d/%d%n", passed, questions.length);
    }
}
Where you'll use itAutomated evaluation catches prompt regressions before they reach production. Run evaluation suites on every prompt change to ensure quality remains stable or improves.
Under the hoodRelevancyEvaluator uses a secondary LLM call to judge whether the answer is relevant to the question. This "LLM-as-judge" pattern is cost-effective for non-critical evaluations but should be supplemented with human review for high-stakes applications.

38High-Throughput Tuning: Connection Pools and Virtual Threads

What & why. LLM API calls are network-bound, not CPU-bound. Java 21+ virtual threads enable blocking HTTP calls to LLM providers without consuming OS threads. Connection pooling for HTTP clients prevents socket exhaustion under high concurrency. Tuning these ensures your Spring AI service handles hundreds of concurrent LLM requests without thread pool starvation.

# Enable virtual threads (Java 21+)

  threads:
    virtual:
      enabled: true

@Bean
public HttpClient httpClient() {
    return HttpClient.create()
        .responseTimeout(Duration.ofSeconds(60))
        .doOnConnected(conn ->
            conn.addHandlerLast(new ReadTimeoutHandler(60))
                .addHandlerLast(new WriteTimeoutHandler(30)))
        .observe(connection ->
            log.debug("Connection: {}", connection.channel()));
}

// Connection pool configuration
@Bean
public ConnectionProvider connectionProvider() {
    return ConnectionProvider.builder("llm-pool")
        .maxConnections(200)
        .maxIdleTime(Duration.ofSeconds(20))
        .maxLifeTime(Duration.ofSeconds(60))
        .pendingAcquireTimeout(Duration.ofSeconds(30))
        .build();
}

43Cost Governance: Meter Registry and Chargeback

This enables cost attribution, budget alerts, and usage-based pricing.

import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.core.instrument.Counter;

public class CostTrackingAdvisor implements RequestResponseAdvisor {
    private final MeterRegistry registry;
    private final CostCalculator costCalc;

    @Override
    public ChatResponse adviseResponse(ChatResponse response,
                                       Map<String, Object> ctx) {
        Usage usage = response.getMetadata().getUsage();
        String tenant = (String) ctx.getOrDefault("tenantId", "default");
        String model = (String) ctx.getOrDefault("model", "unknown");

        Counter.builder("llm.tokens.total")
            .tag("tenant", tenant)
            .tag("model", model)
            .tag("type", "prompt")
            .register(registry)
            .increment(usage.getPromptTokens());

        Counter.builder("llm.tokens.total")
            .tag("tenant", tenant)
            .tag("model", model)
            .tag("type", "completion")
            .register(registry)
            .increment(usage.getGenerationTokens());

        double cost = costCalc.calculate(model, usage);
        Counter.builder("llm.cost.usd")
            .tag("tenant", tenant)
            .register(registry)
            .increment(cost);

        return response;
    }
}
Where you'll use itLLM costs can spiral without governance. Per-tenant metering enables chargeback, budget alerts, and usage-based billing. Grafana dashboards built on Micrometer metrics provide real-time cost visibility.
Under the hoodMicrometer's Counter and Gauge instruments are pushed to Prometheus, Datadog, or CloudWatch via configured exporters. Tags enable multi-dimensional querying by tenant, model, and request type.

@RestController
@RequestMapping("/api/support")
public class SupportController {

public class HrTools {

Document QA Microservice with SSE Streaming + Micrometer Dashboards

Build a document Q&A microservice that ingests PDFs and text files, answers questions via RAG, streams responses to browser clients via SSE, and exposes Micrometer metrics for operational dashboards.

Architecture steps.

  1. Create a Spring Boot 3 WebFlux project with OpenAI and PgVector starters
  2. Build an ingestion API: POST /api/ingest accepts file uploads and processes them through TikaDocumentReader + TokenTextSplitter into PgVector
  3. Configure ChatClient with QuestionAnswerAdvisor for RAG retrieval
  4. Implement SSE streaming endpoint: GET /api/qa/stream?question=...&docId=...
  5. Add Micrometer custom metrics: llm.tokens.total, llm.cost.usd, rag.retrieval.count
  6. Build a Thymeleaf or static HTML page with JavaScript EventSource for real-time streaming display
  7. Configure Prometheus exporter and create Grafana dashboard for LLM metrics
  8. Add error handling with @ControllerAdvice mapping AI-specific exceptions
@RestController
@RequestMapping("/api/qa")
public class QaController {
    private final ChatClient chatClient;
    private final VectorStore vectorStore;

    @GetMapping(value = "/stream",
                produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    public Flux<ServerSentEvent<String>> stream(
            @RequestParam String question,
            @RequestParam String docId) {
        return chatClient.prompt()
            .user(question)
            .advisors(new QuestionAnswerAdvisor(vectorStore,
                SearchRequest.defaults()
                    .withFilterExpression("docId == '" + docId + "'")
                    .withTopK(5)))
            .stream()
            .content()
            .index((i, chunk) ->
                ServerSentEvent.<String>builder()
                    .id(String.valueOf(i))
                    .data(chunk)
                    .build());
    }
}
