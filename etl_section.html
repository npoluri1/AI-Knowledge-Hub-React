🎯 WHAT IS KAFKA?

Apache Kafka is a distributed event streaming platform capable of handling trillions of events per day. Originally developed at LinkedIn, it's now the industry standard for real-time data pipelines and streaming applications.

🛠 CORE CONCEPTS & TOPICS

1. Brokers & Clusters
  • Broker: Single Kafka server instance
  • Cluster: Group of brokers working together
  • Leader/Follower: Partition leaders handle reads/writes
  • Topic: Logical channel for messages
  • Partition: Unit of parallelism within a topic
2. Producers & Consumers
  • Producer: Publishes events to topics
  • Consumer: Subscribes to topics and processes events
  • Consumer Group: Load balancing across consumers
  • Offset: Position of consumer in partition
  • Rebalance: Redistributing partitions when consumers join/leave
3. Storage & Retention
  • Segment: File on disk storing messages
  • Retention: How long messages are kept
  • Log Compaction: Keeping only latest value per key
  • Log Deletion: Removing old segments
  • Tombstone: Marker for deleted records
4. Connect & Streams
  • Kafka Connect: Framework for source/sink connectors
  • Source Connector: Ingests data INTO Kafka
  • Sink Connector: Exports data FROM Kafka
  • Kafka Streams: Client library for stream processing
  • KSQL: SQL interface for stream processing

🎯 WHAT IS FLINK?

Apache Flink is a distributed processing engine for stateful computations over unbounded and bounded data streams. It's the industry standard for stream processing with exactly-once semantics, event time processing, and advanced state management.

🛠 CORE CONCEPTS & TOPICS

1. Execution Model
  • DataFlow: Graph of transformations
  • Operator: Unit of computation (map, filter, etc.)
  • Parallelism: Number of instances per operator
  • Slot: Resource unit in TaskManager
  • Subtask: Parallel instance of an operator
2. State Management
  • Keyed State: State partitioned by key
  • Operator State: State bound to parallel instance
  • Checkpointing: Periodic state snapshots
  • Savepoint: Manual, full state snapshot
  • RocksDB State Backend: Disk-based state storage
3. Windowing & Time
  • Event Time: When event occurred
  • Processing Time: When operator processes event
  • Tumbling Window: Fixed, non-overlapping
  • Sliding Window: Fixed size, overlapping
  • Session Window: Activity-based grouping
4. Table API & SQL
  • Table API: SQL-like API in Java/Scala/Python
  • Flink SQL: Declarative SQL for streaming
  • Catalog: Metadata management
  • Dynamic Tables: Streaming tables updated continuously
  • Temporal Joins: Join with versioned tables

📖 KEY QUERIES & CODE EXAMPLES

-- Flink SQL: Tumbling Window Aggregation
SELECT 
  TUMBLE_START(event_time, INTERVAL '1' HOUR) as window_start,
  TUMBLE_END(event_time, INTERVAL '1' HOUR) as window_end,
  customer_id,
  COUNT(*) as event_count,
  SUM(amount) as total_amount
FROM orders
WHERE status = 'completed'
GROUP BY TUMBLE(event_time, INTERVAL '1' HOUR), customer_id;

-- Flink SQL: Session Window with Gap
SELECT 
  SESSION_START(event_time, INTERVAL '30' MINUTE) as session_start,
  SESSION_END(event_time, INTERVAL '30' MINUTE) as session_end,
  user_id,
  COUNT(*) as actions,
  SUM(value) as session_total
FROM user_events
GROUP BY SESSION(event_time, INTERVAL '30' MINUTE), user_id;

-- Flink SQL: Temporal Join (CDC)
SELECT 
  o.order_id,
  o.amount,
  c.customer_name,
  c.credit_limit
FROM orders o
LEFT JOIN customers FOR SYSTEM_TIME AS OF o.proc_time AS c
  ON o.customer_id = c.id;

🎯 WHAT IS AIRFLOW?

Apache Airflow is an open-source workflow orchestration platform for programmatically authoring, scheduling, and monitoring data pipelines. It uses directed acyclic graphs (DAGs) to define task dependencies and execution order.

🛠 CORE CONCEPTS & TOPICS

1. DAGs & Tasks
  • DAG: Directed Acyclic Graph of tasks
  • Task: Unit of work in a DAG
  • Operator: Template for a task (BashOperator, PythonOperator)
  • TaskFlow: @task decorator for Python functions
  • Dependencies: set_upstream(), set_downstream()
2. Executors & Scaling
  • SequentialExecutor: Single process, local
  • LocalExecutor: Multi-process, local
  • CeleryExecutor: Distributed workers
  • KubernetesExecutor: Dynamic pod per task
  • TaskPool: Concurrency limit per worker
3. Connections & Variables
  • Connections: Stored credentials for external systems
  • Variables: Global key-value storage
  • Hooks: Interface to external systems (S3Hook, PostgresHook)
  • Sensors: Wait for external condition (FileSensor, HttpSensor)
  • XCom: Cross-communication between tasks
4. Advanced Features
  • SubDAGs: Reusable DAG components
  • Branching: BranchPythonOperator for conditional logic
  • Dynamic Task Mapping: Map over inputs (Airflow 2.4+)
  • Datasets: Data-aware scheduling (Airflow 2.4+)
  • Listeners: React to lifecycle events

    def extract_data(**context):
        """Extract data from source API"""
        import requests

        return response.json()

    def transform_data(**context):
        """Transform raw data"""
        raw = context['ti'].xcom_pull(key='raw_data', task_ids='extract')
        transformed = [{'id': r['id'], 'amount': float(r['amt'])} for r in raw]
        context['ti'].xcom_push(key='transformed', value=transformed)
        return transformed

    def load_data(**context):
        """Load to destination"""
        data = context['ti'].xcom_pull(key='transformed', task_ids='transform')
        # Load logic here

    with TaskGroup('quality_checks') as quality:

🎯 WHAT IS DBT?

dbt (data build tool) is a SQL-based transformation tool that enables analytics engineers to transform data in the warehouse using software engineering best practices. It's the industry standard for ELT transformations.

🛠 CORE CONCEPTS & TOPICS

1. Project Structure
  • dbt_project.yml: Project configuration
  • models/: SQL files defining transformations
  • tests/: Data quality tests (schema.yml)
  • macros/: Reusable SQL functions (Jinja2)
  • snapshots/: Slowly changing dimensions (SCD)
2. Materializations
  • View: Default, no storage, always fresh
  • Table: Full refresh on each run
  • Incremental: Only new/changed rows
  • Ephemeral: CTE, not persisted
  • Materialized View: Auto-refreshing view
3. Testing & Documentation
  • Singular Tests: Custom SQL tests
  • Generic Tests: unique, not_null, accepted_values, relationships
  • Sources: Define upstream data sources
  • Exposures: Downstream consumers (dashboards, models)
  • Documentation: Auto-generated docs site
4. Advanced Features
  • Merge Keys: For incremental models
  • On Schema Change: sync_all_columns, append_new_columns
  • dbt Packages: Shared code (dbt_utils, dbt_expectations)
  • Jobs: Scheduled runs with alerts
  • Semantic Layer: Metric definitions for BI tools

2. Spark SQL & DataFrame
  • DataFrame: Distributed collection of data
  • Dataset: Type-safe DataFrame (Scala/Java)
  • Catalyst Optimizer: Query optimization
  • Tungsten:: Memory management
  • Parquet/ORC: Columnar storage formats
3. Structured Streaming
  • Input Source: Kafka, Files, Socket

  • Trigger: ProcessingTime, Once, AvailableNow

4. Performance Tuning
  • Partitioning: repartition(), coalesce()

  • Caching: persist(), cache()
  • AQE: Adaptive Query Execution (Spark 3)

# PySpark: ETL Pipeline
from pyspark.sql import SparkSession
from pyspark.sql.functions import *

spark = SparkSession.builder \
    .appName("ETL Pipeline") \
    .config("spark.sql.shuffle.partitions", "200") \
    .config("spark.sql.adaptive.enabled", "true") \
    .getOrCreate()

# Read from Delta Lake
df = spark.read.format("delta") \
    .load("/mnt/data/raw/orders")

# Transformations
transformed = df \
    .filter(col("status") == "completed") \
    .withColumn("amount_usd", col("amount") * col("exchange_rate")) \
    .withColumn("order_date", to_date(col("timestamp"))) \
    .groupBy("customer_id", "order_date") \
    .agg(
        sum("amount_usd").alias("total_spent"),
        count("*").alias("order_count"),
        avg("amount_usd").alias("avg_order_value")
    )

# Write to Delta Lake with merge
transformed.write \
    .format("delta") \
    .mode("overwrite") \
    .partitionBy("order_date") \
    .save("/mnt/data/processed/customer_daily")

# Structured Streaming
stream_df = spark.readStream \
    .format("kafka") \
    .option("kafka.bootstrap.servers", "kafka:9092") \
    .option("subscribe", "orders") \
    .load()

parsed = stream_df.select(
    from_json(col("value").cast("string"), schema).alias("data")
).select("data.*")

windowed = parsed \
    .withWatermark("event_time", "10 minutes") \
    .groupBy(
        window("event_time", "5 minutes"),
        "category"
    ) \
    .agg(sum("amount").alias("total"))

windowed.writeStream \
    .format("console") \
    .outputMode("update") \
    .start()

🎯 WHAT IS AIRBYTE?

Airbyte is an open-source data integration platform that provides ELT connectors. It's the open-source alternative to Fivetran with a growing ecosystem of 350+ connectors and a focus on customization.

🛠 CORE CONCEPTS & TOPICS

1. Architecture

  • Connector Builder: Low-code connector creation

2. Connector Types
  • Source Connector: Extracts data from source
  • Destination Connector: Loads to destination
  • Custom Connector: Build your own (Python)
  • Community Connector: Open-source contributions
  • AI Connector: LLM-powered extraction
3. Sync Modes
  • Full Refresh Overwrite: Replace all data
  • Full Refresh Append: Add new data
  • Incremental - Append: New rows only
  • Incremental - Deduped: New + deduplicate
  • Change Data Capture: Track changes
4. Deployment Options
  • Docker Compose: Local development
  • Kubernetes: Production scale
  • Cloud (Airbyte Cloud): Managed service
  • Self-Hosted: Full control
  • Hybrid: Self-hosted + cloud features

🎯 WHAT IS DAGSTER?

Dagster is a modern data orchestrator for machine learning and analytics. It uses a software-defined assets approach where you define what you want to build (assets) rather than how to build it (tasks).

🛠 CORE CONCEPTS & TOPICS

1. Asset-Based Paradigm
  • Asset: A file, table, or dataset to be produced
  • Asset Key: Unique identifier for an asset
  • Asset Graph: DAG of asset dependencies
  • Asset Materialization: Event of producing an asset
  • Asset Check: Quality check on an asset
2. Ops & Jobs
  • Op: Unit of computation (like Airflow task)
  • Job: Graph of ops with config
  • Graph: Static definition of dependencies
  • Config: Schema for runtime parameters
  • IO Manager: Handles asset persistence
3. Resources & Sensors
  • Resource: External system connection
  • Sensor: Triggers runs based on conditions
  • Schedule: Cron-based triggers
  • Run Coordinator: Manages concurrent runs
  • Partitions: Time-based or static splits
4. Software-Defined Lifecycle
  • Development: Local, fast iteration
  • Testing: Unit tests, integration tests
  • Deployment: Docker, Kubernetes, ECS
  • Monitoring: Dagster UI, logs, alerts
  • Observability: Asset health, freshness

📖 KEY CODE EXAMPLES

# Dagster: Asset-Based Pipeline
from dagster import (
    asset, AssetIn, AssetKey, Definitions,
    DailyPartitionsDefinition, freshness_policy
)
import pandas as pd
from datetime import timedelta

# Define partitioned asset
@asset(
    partitions_def=DailyPartitionsDefinition(start_date="2024-01-01"),
    freshness_policy=freshness_policy(maximum_lag_minutes=60),
)
def daily_orders(context) -> pd.DataFrame:
    """Fetch daily orders from API"""
    partition_date = context.partition_key
    df = fetch_orders(partition_date)
    context.log.info(f"Fetched {len(df)} orders")
    return df

# Asset with dependency
@asset(
    ins={"orders": AssetIn("daily_orders")},
    io_manager="s3_io_manager",
)
def orders_summary(orders: pd.DataFrame) -> pd.DataFrame:
    """Aggregate orders by customer"""
    return orders.groupby('customer_id').agg(
        total=('amount', 'sum'),
        count=('id', 'count')
    ).reset_index()

# IO Manager for S3
from dagster import IOManager
import pyarrow as pa
import pyarrow.parquet as pq

class S3IOManager(IOManager):
    def __init__(self, bucket):
        self.bucket = bucket
    
    def handle_output(self, context, obj):
        table = pa.Table.from_pandas(obj)
        path = f"s3://{self.bucket}/{context.asset_key.path}.parquet"
        pq.write_table(table, path)
    
    def load_input(self, context):
        path = f"s3://{self.bucket}/{context.asset_key.path}.parquet"
        return pq.read_table(path).to_pandas()

# Definitions
defs = Definitions(
    assets=[daily_orders, orders_summary],
    resources={
        "s3_io_manager": S3IOManager(bucket="my-bucket"),
    },
)
